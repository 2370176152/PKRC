## 三、待建模块（3 个）与依赖图

```
        ┌───────────────────────────────────────────────┐
        │  ① pointer-manager      （唯一 DOM 入口）      │
        │  挂 1 个 pointerdown/up/move/wheel 监听于 canvas│
        │  产出 PointerSample → 交给 gesture-resolver     │
        └───────────────┬───────────────────────────────┘
                        ↓
        ┌───────────────────────────────────────────────┐
        │  gesture-resolver（F-6 已有）                  │
        │  tap / long-press / drag / swipe / wheel      │
        └───────────────┬───────────────────────────────┘
                        ↓
        ┌───────────────────────────────────────────────┐
        │  input-arbiter（F-6 已有）                     │
        │  设备标记 / 同帧去重 / 键鼠切换冷却 / 兜底开关  │
        └───────────────┬───────────────────────────────┘
                        ↓
        ┌───────────────────────────────────────────────┐
        │  ② interaction-registry（声明式注册表）        │
        │  按当前场景查 scene-adapters → specs() → HitBox │
        │  命中 ⇒ 产出 ActionRequest（button/cursor/     │
        │         scroll/custom）                        │
        └───────────────┬───────────────────────────────┘
                        ↓
        ┌───────────────────────────────────────────────┐
        │  ③ legacy-bridge（落到上游）                   │
        │  button → ui.processInput(Button)             │
        │  cursor → ui.setCursor(...)                   │
        │  scroll → 上游滚动处理                         │
        └───────────────────────────────────────────────┘
```

**三条铁律**（承接 F-7 §3，**必须遵守**）：

1. **唯一 canvas 入口** —— 只在 `pointer-manager` 里挂监听；
   **禁止**在各 UI handler 里零散加 `pointerdown`。
2. **设备仲裁单点** —— 所有动作先过 `input-arbiter`，`lastDevice` 是**唯一**设备真相。
3. **鼠标不写 `"mouse"`** —— `inputMethod` 的 3 处读点把它当**精灵图集 key**
   （`run-info`×2 / `starter-select` / `pokedex-page`）；鼠标复用
   `controller_type:"keyboard", isTouch:false` 通道 ⇒ **上游 0 改动**（F-9 做法甲）。

## 五、⚠️ 与 A4 补迁区域的**冲突边界**

S6 要改上游文件，而 A4-00b / A3-补 也在改上游文件 —— **必须提前划界，避免互相覆盖**。

| 上游文件 | S6 需要做什么 | A4 补迁是否也动它 | 冲突风险 | 处置 |
|---|---|---|---|---|
| `src/battle-scene.ts` | 读 `inputMethod`（:344）；挂 canvas 入口 | 🟡 **可能**（patch 宿主：`initGameSpeed` 等） | **中** | S6 **只读不写** `inputMethod`；canvas 挂载放**新文件**，不改 `battle-scene` 结构 |
| `src/ui-inputs.ts` | `detectInputMethod`（:36）后挂**仲裁前钩子** | 🟡 **可能**（`UiInputs.buttonSpeedChange` 在 patch 挂账清单里） | **高** | 约定：A4 先完成该文件补迁 → S6 再改；**由 M5 后统一排期** |
| `src/touch-controls.ts` | 复用 `bindKey`（虚拟手柄，DOM 层）；**恢复被魔改移除的 pointerdown** | 🔴 **否**（不在 32 宿主清单） | 低 | S6 独占 |
| `src/ui/ui.ts` | 调 `processInput` / `setCursor`（**已有 API，不改**） | 🔴 否 | 无 | 只调用 |
| 6 个模态族文件<br>（modal / form-modal / admin / login-register / oauth / move-touch-controls） | **复用**其已有 canvas `pointerdown`（上游原生） | 🟡 部分（form-modal 等属 UI 层，可能转 U 组） | **中** | 只读复用，不改 |
| `src/input/**`（新建） | S6 主体 | 🔴 否（新目录） | 无 | S6 独占 |

### 划界三条规则

1. **S6 不修改任何已被 A4 补迁"占名"的文件**；需要时**先报，后改**。
2. **canvas 入口只在新文件里挂**（`pointer-manager.ts`），用**运行时注册**接入
   （在 `initializeGame()` 之后），避免改 `battle-scene.ts` 的构造流程。
3. **`ui-inputs.ts` 是唯一高风险交汇点** ⇒ 排期上**排在 A4 补迁该文件之后**；
   若 A4 未完成，S6 先做不依赖它的 5 个模块（pointer-manager / registry / bridge / adapter）。

> **与 U 组的边界**：`TargetSelectUiHandler` / `CommandUiHandler` / `RunEntryContainer` / `SessionSlot`
> 属 **UI 层改写**（A4-00b 已建议转 U 组）。S6 的 adapter 可先按**现有** UI 结构写
> （`specs()` 基于 HitBox，不依赖 handler 内部实现）⇒ **S6 与 U 组解耦**。
