#### 4.1 🔴 日志采集：先说清一个盲区

**现状核实（2026-10-20）**：

| 机制 | 输出去向 | 能否拿到实玩日志 |
|---|---|---|
| `debugLog(category, ...args)`（`mod-utils.ts`） | `console.log` ⇒ **浏览器 console** | ❌ 不进文件 |
| `game/server/logger.cjs` + `--log-dir` | **Node 服务进程** stdout/stderr ⇒ `game/logs/` | ❌ 不含渲染器 console |

> **⇒ 两者不通。`game/logs/` 抓不到浏览器 console —— 这是现有机制的盲区。**
> **不能假设"开了日志就有实玩日志"，必须显式指定采集路径。**

**采集方案（默认走零改动路径）**：

| 步 | 操作 | 说明 |
|---|---|---|
| 1 | **开日志** | 启动后访问 `?debug=all`（或 console 里 `localStorage.PT_DEBUG='all'` 再刷新） |
| 2 | **游玩** | 正常实玩，日志实时进 DevTools Console |
| 3 | **取日志** | DevTools → Console → 右上齿轮/右键 → **Save console log…** ⇒ 存成 `logs/play-<模式>-<时间>.log` |
| 4 | **补会话头** | 每局开头手动记一行：`=== MODE=<模式> BUILD=<index-*.js> TIME=<ISO> ===` |

> **为什么默认用 DevTools 原生保存**：**零改动、零新工具**，符合铁律。
> **备选（仅在日志量大到没法保存时启用）**：给 `debugLog` 加环形缓冲 + `window.__PT_LOG` 导出
> —— 属**改既有文件**（`mod-utils.ts`），需重跑一次 `vite build --mode app` 并同步产物。

**日志要能回答什么（不然白记）**：

| # | 问题 | 靠什么日志回答 |
|---|---|---|
| 1 | 这局跑到哪儿了 | 模式头 + 阶段/波次标记 |
| 2 | 有没有崩 | `error` 级别 + 栈 |
| 3 | 战斗数值对不对 | 出招者 / 招式 / 伤害值 / HP 变化 |
| 4 | PT 结算通不通 | `askSavePokemonUsage` / `proceedWithVictory` / `addPt` 的入参与结果 |
| 5 | 有没有静默失效 | `[系统]` 标记的 debug 输出是否按预期出现 |

### 8.2 突破的技术核心

**死结**（实测）：`document.body.innerText.length === 0` —— 全部 UI 渲染在单个 canvas 里，
`Phaser.GAMES` 不可用、`window.game` 不存在 ⇒ **DOM 断言对游戏内画面完全失效**。
这就是第 5~7 阶段所有 route 只能给"画面变了"这种弱证明 ⇒ 全部 `unproven` 的根因。

**解法**（两件）：
1. **一行只读观测句柄**（`src/main.ts`）：`Object.defineProperty(window, "__PKRC_GAME__", { value: game, writable: false, configurable: false })`
   —— **纯观测**：不创建、不修改、不驱动任何逻辑；去掉不影响游戏行为
2. **`catalog.mjs` 用 `waitFor` 读真实状态**：`waveIndex` / `getPlayerParty().length` / `phaseManager` 当前 Phase

**结果**：`reachProof` 由 `none` → **`dom`**，判定由 `unproven` → **`pass`**。
