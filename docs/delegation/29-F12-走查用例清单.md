## 二、每个检查点的四要素（验收 ②）

| 要素 | 字段 | 说明 |
|---|---|---|
| **如何到达** | `arrival` + `keys[]` | 文字描述 + **可执行**按键序列（F-10 直接跑） |
| **断言什么** | `asserts[]` | `state`(表达式) / `visual`(截图) / `noNewErrors`(不得新增异常) |
| **期望结果** | `expect` | 每个断言的期望值或期望外观 |
| **判定方式** | `judgement` | `assert` / `diff` / `ai` —— 对应 O-9b 三级判据 |

```js
{
  id: "boot.welcome-popup",
  label: "首次启动欢迎弹窗",
  arrival: "就绪后等待 splash 淡出，主菜单上的欢迎弹窗稳定",
  keys: [],
  reachability: "verified",
  asserts: [
    { kind: "expr",  expr: "document.body.innerText.length > 0", expect: "存在 DOM 文本（弹窗）", judgement: "assert" },
    { kind: "visual", expect: "弹窗标题/按钮文案与 A 版一致",                 judgement: "diff" },
    { kind: "noNewErrors", expect: "未新增未捕获异常",                       judgement: "assert" },
  ],
}
```

## 四、双产物可复现设计（验收 ③）

| 保障 | 做法 |
|---|---|
| 同一存档 | 双跑共用同一 `--inject`（`localStorage` 注入，页面脚本前生效）；无注入时用**全新 profile**（各自空档，状态一致） |
| 同一操作序列 | 场景 `keys[]` 是**数据**，A/B 两侧执行**同一数组**；输入经 `input-arbiter` 仲裁，设备切换行为一致 |
| 同一捕获点 | 每点截图前先 `settle`（连续两帧变化率 ≤ 阈值），消除过渡帧抖动 |
| 同一资源 | A 版资源不完整 ⇒ 静态服务器**叠加 B 的资源层**，两版共享同一份 audio/fonts/images，差异只来自 `assets/` |
| 隔离 | 端口 `0` + 独立 profile ⇒ A/B **并跑不互相污染** |

## 六、判定方式分布（验收 ④）

| 判定 | 适用范围 | 说明 |
|---|---|---|
| **① 状态/数值断言** | 全部点（每条都带 `noNewErrors`） | 最硬；机器可判 |
| **② 像素 diff** | 全部点（每点必截图） | A｜B 差异率 + 热区 |
| **③ AI 视觉审阅** | **仅灰区** | ①② 均不能定的点，逐张看图裁定；**不得单独作通过依据** |

> 目录里的 `visual` 断言标注了 `judgement: "diff"`（可机器判）——
> 只有实测出现「像素 diff 无法定性」时，才升级到 ③。
