## 一、设计依据（为什么这样定）

来自 U-1（`16-UI-上游文本API调研.md`）的三条硬结论：

1. **上游已有文本工厂**：`addTextObject` / `setTextStyle` / `addBBCodeTextObject` / `addTextInputObject` / `getTextStyleOptions`（`src/ui/text.ts`，700 行）
2. **上游无字号 Token 层**：56 个 `TextStyle` 里 15 个共用 96px，字号只是样式的附属属性
3. **最小侵入点**：`getTextStyleOptions()` 内、`Object.assign` 之前，加一段 `level` 解析

> 因此本契约**不新增任何工厂函数**，只在既有入口上加一个可选维度。
> 这与 v1 派单设想的「新建 `pkrc/theme/text-factory.js`」**有本质区别** —— v1 的方案会在上游工厂之外长期并存两套入口，正是改版 108 处裸字号的成因。

## 二、`theme-config.json`（🔒 冻结 · 合法 JSON 无注释）

**路径**：`src/config/theme-config.json`（或 `game/server/dist/pkrc/config/theme-config.json`，由全栈按 A3-01 规范定）

```json
{
  "scale": {
    "logicalWidth": 320,
    "logicalHeight": 180,
    "physicalWidth": 1920,
    "physicalHeight": 1080,
    "scaleFactor": 0.1666666667,
    "mode": "FIT",
    "dprAware": true
  },
  "font": {
    "family": "emerald",
    "scaleFactor": 1.0,
    "levels": {
      "display": 128,
      "title": 66,
      "heading": 60,
      "body": 54,
      "label": 48,
      "caption": 42,
      "micro": 36
    },
    "lineHeight": {
      "body": 1.35,
      "compact": 1.15
    },
    "baseFontSize": 96
  },
  "spacing": {
    "xs": 4,
    "sm": 8,
    "md": 12,
    "lg": 16,
    "xl": 24
  },
  "palette": {
    "inherit": true,
    "extra": {}
  },
  "legacy": {
    "rewriteFontSizeLiterals": true,
    "allowedLiterals": [0],
    "allowedLineSpacing": [0, 2, 3, 5]
  },
  "i18n": {
    "namespacePrefix": "pkrc",
    "fallback": "zh-CN"
  }
}
```

### 2.1 Schema 字段说明（冻结语义）

| 字段 | 类型 | 冻结值 | 语义 | 消费方 |
|---|---|---|---|---|
| `scale.logicalWidth/Height` | int | 320 / 180 | **逻辑画布**（上游 `hs=320, xs=180`） | 全栈 |
| `scale.physicalWidth/Height` | int | 1920 / 1080 | 物理画布 | 全栈 |
| `scale.scaleFactor` | float | `0.1666666667` | 上游恒定 1/6 缩放 | 全栈 |
| `scale.mode` | enum | `"FIT"` | Phaser ScaleManager 模式 | 全栈 |
| `scale.dprAware` | bool | `true` | 高 DPI 适配 | 全栈 |
| `font.family` | string | `"emerald"` | 主字体（另有 `pkmnems` 用于 `PARTY` 系） | 全栈 |
| `font.scaleFactor` | float | `1.0` | 全局字号微调（回退旋钮） | 全栈 |
| `font.levels.*` | int | 见上 | **7 级 Token 值**（逻辑像素） | 全栈 / 前端 |
| `font.lineHeight.body` | float | `1.35` | 正文行高倍率 | 全栈 |
| `font.lineHeight.compact` | float | `1.15` | 紧凑行高倍率 | 全栈 |
| `font.baseFontSize` | int | `96` | 上游基准字号（对照用） | 全栈 |
| `spacing.*` | int | 4/8/12/16/24 | 4px 栅格 | 全栈 / 前端 |
| `palette.inherit` | bool | `true` | 是否继承上游 `TextStyle` 配色 | 全栈 |
| `palette.extra` | object | `{}` | **新增配色必须在此登记**，禁止内联 hex | UI |
| `legacy.rewriteFontSizeLiterals` | bool | `true` | 是否归一裸字号（**回退开关**） | 全栈 |
| `legacy.allowedLiterals` | int[] | `[0]` | **必须保留的裸字号白名单** | 全栈 |
| `legacy.allowedLineSpacing` | int[] | `[0,2,3,5]` | 必须保留的紧凑行距 | 全栈 |
| `i18n.namespacePrefix` | string | `"pkrc"` | 新建文案文件的键前缀 | UI / 全栈 |
| `i18n.fallback` | string | `"zh-CN"` | 回退语言 | 全栈 |

### 2.2 与 v1 派单 / `visual-spec.md` 的差异（冻结理由）

| 字段 | 旧值 | **冻结值** | 理由 |
|---|---|---|---|
| `scale.baseWidth/baseHeight` | 1920 / 1080 | **`logicalWidth/Height` = 320/180 + `physicalWidth/Height` = 1920/1080 + `scaleFactor`** | U-1 实测：逻辑与物理是两套，必须分开声明（U-1 §四） |
| `legacy.allowedLiterals` | `[]` | **`[0]``** | L472 `fontSize:0` 是隐形占位，归一成 36 会显示文字（11 文档 W-1） |
| `legacy.allowedLineSpacing` | 未定义 | **新增 `[0,2,3,5]`** | 实测 7 种 `lineSpacing`，`<8` 的 4 值是紧凑场景（11 文档 §4.1） |
| `font.baseFontSize` | 未定义 | **新增 `96`** | 上游 `defaultFontSize`，Token 化时需对照（U-1 §1.2） |

## 三、`text-factory` 契约（🔒 冻结）

### 3.1 核心决策：扩展上游，不新建

```ts
// src/enums/text-size-level.ts  （新增，96 行量级）
export const TextSizeLevel = Object.freeze({
  DISPLAY: 128,
  TITLE: 66,
  HEADING: 60,
  BODY: 54,
  LABEL: 48,
  CAPTION: 42,
  MICRO: 36,
} as const);
export type TextSizeLevel = (typeof TextSizeLevel)[keyof typeof TextSizeLevel];
```

### 3.2 扩展后的 `getTextStyleOptions`（侵入点）

**文件**：`src/ui/text.ts`（上游，700 行）
**位置**：`getTextStyleOptions()` 函数内，`switch (style)` 之后、`Object.assign(styleOptions, extraStyleOptions)` **之前**

```ts
// ↓↓↓ 新增块（约 10 行）↓↓↓
if (extraStyleOptions?.level !== undefined) {
  const px = TextSizeLevel[extraStyleOptions.level];
  if (px !== undefined) {
    styleOptions.fontSize = `${px}px`;
  }
}
// ↑↑↑ 新增块结束 ↑↑↑
```

**为什么在这个位置**：
- ✅ 在 `switch` 之后 → 覆盖 TextStyle 自带的 fontSize（如 `PARTY` 的 48）
- ✅ 在 `Object.assign` 之前 → 仍允许 `extraStyleOptions.fontSize` 显式覆盖（白名单/动态字号场景）
- ✅ 不碰 `scale` / `shadowColor` / `padding` → 视觉其余部分零变化

### 3.3 类型扩展

```ts
// src/types/ui.ts （或 text.ts 内）
export interface TextStyleOptions {
  /** 字号层级 Token。设置后覆盖 TextStyle 自带 fontSize */
  level?: TextSizeLevel;
  /** 显式字号。优先级高于 level，用于白名单与动态字号 */
  fontSize?: string | number;
}
```

### 3.4 消费侧 API（前端 / UI 直接用）

```ts
// 统一入口（上游既有，签名不变，只多一个可选字段）
addTextObject(x, y, content, style: TextStyle, { level: TextSizeLevel.BODY })

// 改样式
setTextStyle(obj, style, { level: TextSizeLevel.LABEL })

// 富文本
addBBCodeTextObject(x, y, content, style, { level: TextSizeLevel.CAPTION })
```

**约束（冻结）**：

| # | 规则 |
|---|---|
| C-1 | **禁止**新增 `createText()` / `label()` 等平行工厂入口 |
| C-2 | **禁止**在 `extraStyleOptions` 之外传裸 `fontSize:"Npx"`（白名单除外） |
| C-3 | 白名单场景必须显式写 `fontSize`，且值 ∈ `legacy.allowedLiterals` |
| C-4 | 动态字号（`setFontSize(变量)`）**不得**改为 `level` |
| C-5 | `Je` 对象升级为 7 级后，**禁止**再新建第二套 Token 常量 |

### 3.5 动态字号豁免清单（冻结）

以下位置**不得** Token 化（U-1 §5 + 11 文档 §三实证）：

| 位置 | 代码 | 原因 |
|---|---|---|
| L1033 守门员 HUD | `guardianTalentText.setFontSize(m.length>4?"30px":"40px")` | 按天赋条数自适应 |
| L456 消息框 | `O.setFontSize(this.messageFontSize(I))` | 按文本高度反算 |
| L472 三被动 | `{fontSize:"0px"}` | 隐形占位（白名单） |

## 四、完整示例（🔒 冻结 · 1 个）

### 4.1 改造前（改版现状 · 裸字号）

```ts
// 产物 L372「天赋历史」标题 —— 裸字号 + F.SETTINGS_LABEL
const title = addTextObject(20, 15, "天赋历史", TextStyle.SETTINGS_LABEL, { fontSize: "70px" });

// 产物 L998「PT HUD」—— 裸字号
const ptText = addTextObject(canvas.width / 6 - 2, 0, "", TextStyle.PARTY, { fontSize: "54px" });
```

### 4.2 改造后（Token 化 · 冻结范式）

```ts
import { TextSizeLevel } from "#enums/text-size-level";

// 「天赋历史」标题：70px 野生值 → title token（66px）
const title = addTextObject(20, 15, i18next.t("pkrc.talent.history.title"),
  TextStyle.SETTINGS_LABEL, { level: TextSizeLevel.TITLE });

// 「PT HUD」：54px 野生值 → body token（54px，零变化）
const ptText = addTextObject(canvas.width / 6 - 2, 0, "",
  TextStyle.PARTY, { level: TextSizeLevel.BODY });
```

### 4.3 改造前后对照

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 字号 | `{ fontSize: "70px" }` 裸值 | `{ level: TextSizeLevel.TITLE }` → 66px |
| 文案 | `"天赋历史"` 内联中文 | `i18next.t("pkrc.talent.history.title")` |
| 配色 | `TextStyle.SETTINGS_LABEL` | **不变**（上游既有） |
| 阴影 / padding | 上游默认 | **不变** |
| 缩放 | `setScale(1/6)` | **不变** |
| 视觉变化 | — | 70 → 66px（−4px，走查项 R-B） |

## 五、`Je` 对象升级方案（冻结）

改版已有 `Je = {title:66, row:60, body:54, small:48, tiny:42}`（149 处调用）。

**冻结方案**：扩展为 7 级，**键名保持向后兼容**，新增两级。

```ts
// 改造后（src/data/... 或就近定义）
export const Je = {
  // 原有 5 键（149 处调用零改动）
  title:  TextSizeLevel.TITLE,    // 66
  row:    TextSizeLevel.HEADING,  // 60  ← 语义更清晰，值不变
  body:   TextSizeLevel.BODY,     // 54
  small:  TextSizeLevel.LABEL,    // 48
  tiny:   TextSizeLevel.CAPTION,  // 42
  // 新增 2 键
  display: TextSizeLevel.DISPLAY, // 128
  micro:   TextSizeLevel.MICRO,   // 36
};
```

| 键 | 旧值 | 新值 | 调用数 | 改动 |
|---|---|---|---:|---|
| `title` | 66 | 66 | 6 | 零 |
| `row` | 60 | 60 | 1 | 零 |
| `body` | 54 | 54 | 24 | 零 |
| `small` | 48 | 48 | 48 | 零 |
| `tiny` | 42 | 42 | 70 | 零 |
| `display` | — | **128** | 0 | 新增 |
| `micro` | — | **36** | 0 | 新增 |

> ✅ **149 处现有调用零改动**；新增的 `display`/`micro` 供 S7-2 收敛 108 处裸值时使用。
