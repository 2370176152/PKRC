### 2.2 任务 1.1：`server.cjs` 改造

**目标 A：暴露可复用的服务工厂**（供 S7 的 Electron 主进程内嵌调用）

```js
// game/server/server.cjs
/**
 * 创建 Express 应用（不监听），供单机启动与 Electron 内嵌共用。
 * @param {{ staticDir?: string, logger?: Logger }} opts
 * @returns {import('express').Express}
 */
function createApp(opts = {}) { /* ... */ }

/**
 * 启动服务。port=0 时使用动态端口（Electron 内嵌场景）。
 * @param {{ port?: number, staticDir?: string, logger?: Logger }} opts
 * @returns {Promise<{ port: number, close: () => Promise<void>, server: import('http').Server }>}
 */
async function startServer(opts = {}) { /* ... */ }

module.exports = { createApp, startServer };
```

**目标 B：支持新启动参数**

| 参数 | 行为 |
|---|---|
| `PORT`（环境变量） | 保持 `process.env.PORT \|\| 8000`（**向后兼容，不可改语义**） |
| `--serve-only` | **只起服务，不起 Electron**（排错 / 远程访问 / CI 用） |
| `--no-open` | 起服务 + Electron，但不自动打开浏览器 |
| `--dev` | 保留控制台输出 + 更详细日志级别 |
| `--static-dir=<path>` | 静态目录可配置（默认 `./dist`） |

**⚠️ 硬约束**：
- **不得改变现有默认行为**：无参数启动时，行为必须与改造前**完全一致**（端口 8000、静态目录 `./dist`）
- **不得引入新的运行时依赖**（保持 Express 4；便携 Node 环境下新增依赖会带来部署风险）
- 服务必须支持**优雅关闭**：`close()` 返回 Promise，等所有连接释放后再回 `resolve`

### 2.3 任务 1.2：日志系统（与全栈共同定义契约）

**这是你与全栈的接口契约，需双方确认后冻结。**

**日志路径规范**：

```
game/logs/node-<yyyyMMdd-HHmmss>.log
```

- **不再用固定名** `node_output.txt` / `node_error.txt`（覆盖式，历史丢失）
- 轮转保留**最近 N 份**（建议 N=10，可配置）
- 单文件应包含 stdout + stderr 合流，并带级别前缀

**日志行格式（建议，需与全栈确认）**：

```
[2026-10-13 13:15:53.123] [INFO ] server listening on http://localhost:8000
[2026-10-13 13:15:54.456] [ERROR] EADDRINUSE: port 8000 in use
```

**全栈需要的能力**（你在 `server.cjs` 中提供）：

```js
// 供启动器判断是否需要弹错误提示
logger.hasError();        // 本次运行是否出现过 ERROR
logger.currentLogPath();  // 当前日志文件绝对路径（启动器用于弹窗展示）
```

**弹窗触发条件**（全栈实现弹窗，你提供信号）：
- 进程非 0 退出，**或**
- 端口探测超时，**或**
- 日志中出现 ERROR

**成功启动：静默**（不弹窗、不闪黑框）。

### 2.4 任务 1.3：端口策略

## 三、S7 服务侧（S1 稳定后，与全栈协作）

### 3.1 你的交付：内嵌服务 API

全栈的 `electron-main.cjs` 会这样调用你的代码：

```js
// game/electron-main.cjs（全栈写，你提供被调用的 API）
const { startServer } = require('./server/server.cjs');

const { port, close } = await startServer({ port: 0 });   // 动态端口
win.loadURL(`http://localhost:${port}/`);

app.on('before-quit', async () => { await close(); });      // 优雅关闭
```

**你必须保证**：
- `startServer({port: 0})` 返回**真实端口**（从 `server.address().port` 读取）
- `close()` 在 Electron 退出前**必定 resolve**（超时保护，建议 3s）
- 服务不假设自己被独立进程承载（不调 `process.exit`）

### 3.2 S7 验收（服务侧部分）

| # | 验收项 | 判据 |
|---|---|---|
| 7-A | 动态端口 | `startServer({port:0})` 返回可用端口，无固定端口占用 |
| 7-B | 优雅关闭 | Electron 退出 → 服务关闭 → 无残留端口 |
| 7-C | 静态资源 | 通过动态端口访问，全部资源正常加载（含 `pkrc/`） |

### 4.1 背景（为什么要做）

计划书根因 A：**产物即源码**——改一个字号要改压缩后的单行；chunk 哈希随上游更新而变，补丁全部失效。R8 风险等级：**高（长期）**。

| 维度 | A. 维持现状 | B. 锚点补丁 + 外置模块层（本次） | C. 源码化 |
|---|---|---|---|
| 可维护性 | 差 | 好 | **最好** |
| 前置成本 | 无 | 低 | **高** |
| 是否解决无源码问题 | 否 | 部分 | **是** |

本次走 B，**长期并行准备 C**。你的任务就是评估 C 的可验证性。
