### 0.2 🔴 本阶段最重要的变化：关键路径多了两个环节

第二阶段 A3-13 实测暴露了一个**原派单未预见的结构性缺口**：

```
原假设的关键路径（第二阶段派单）:
  A3 迁移完成 → A4 等价性验证 → A5 产物切换

实测的真实关键路径:
  A3 迁移完成
      ↓
  【新增 ①】环境修复 —— vite7/vite8 配置错配 + assets 子模块未初始化
      ↓              （否则 7 处 tsc 错 + 签名无法复测）
  【新增 ②】接入锚点 —— 22 个迁移文件并入锚点树 src/
      ↓              （否则魔改符号根本不在构建里，等价性验证无对象）
  【新增 ③】签名一致复测 —— 消 A3-13 的 58.51% 挂账
      ↓
  A4 等价性验证 → A5 产物切换 → M4 / M5
```

**证据**：A3-13 §5.3 指出 1,122 个未命中符号中，第①类就是「迁移产物尚未接入锚点树」；
本次构建的是「锚点树 + A3-02/03/04 改动」，**不含** `A3-migration/src/` 的 22 个迁移文件。

> **这是本阶段的第一优先级原因**：
> 不做「接入锚点」，A4 的走查与验证**没有验证对象**——会变成"验证一个不含魔改的构建"，纯属空转。

### 0.4 🔴 O-5 决议（2026-10-14）：**M3 必须先修完才能判**

> **项目所有者裁定**：不采用「挂账」口径。**签名一致必须先达标，M3 才判定。**

**这条裁定把 A4-00b 从「记录性复测」升格为「阶段硬卡点（Hard Gate）」**：

| 变化 | 原（挂账口径） | 现（先修完口径） |
|---|---|---|
| A4-00b 性质 | 记录新覆盖率，残差定性即可 | **必须达标**：残差中「迁移缺陷」类必须清零 |
| M3 判定 | 条件达成（挂账） | **未达标即 M3 不成立** |
| A4 可否启动 | 可与 A4-00b 并行 | **A4-00b 未过，A4 一律不得启动** |
| 排期风险 | 低 | ⚠️ **中**：若 A4-00b 超期，M4 / M5 顺延 |

**A4-00b「达标」的明确定义**：

| # | 条件 | 判定 |
|---|---|---|
| ① | `vite build` EXIT=0 | 硬性 |
| ② | 残差中**「迁移缺陷」类 = 0** | **硬性**（这是 M3 的实质含义） |
| ③ | 残差中「tree-shake 差异」「依赖噪声」类**逐条已定性** | 硬性（允许存在，但必须解释清楚） |
| ④ | 核心上游符号（`BattleScene` / `Pokemon` / `Move` / `Ability` / `BattlerTag` / `Modifier` / `Phase` 等）**100% 命中** | 硬性 |
| ⑤ | 11 个自研系统符号**全部命中**（不再是「未接入」状态） | 硬性 |

> ④⑤ 是「② + 接入锚点」的直接推论：接入锚点做完后，上一轮 1,122 个未命中的
> 第①类（迁移未接入）**应当全部转为命中**。若仍有剩余，就是真缺陷。

### 0.5 时序问答：**后端环境修复 vs 全栈推进到 M5，先后顺序怎么排？**

**一句话答案：B-5 是整条链的第一环，必须最先完成；全栈的 A4-00 等它，但全栈不空转。**

#### 严格串行的部分

```
B-5 环境修复（后端 10-15~10-16）
      ↓  硬前置
A4-00 接入锚点（全栈 10-16~10-19）
      ↓
A4-00b 签名复测（全栈 10-19~10-20）  ⛔ M3 硬卡点（O-5 决议）
      ↓  M3 判定通过才可继续
A4-01~04 等价性验证（全栈 10-20~10-23）  → M4
      ↓
A5-01~03 切换与交接（全栈 10-26~10-28，需 B-7 完成）  → M5
```

#### 为什么 B-5 必须在 A4-00 之前（三条硬理由）

| # | 理由 | 后果（若不先修） |
|---|---|---|
| 1 | **A4-00 的验收标准是「全仓 tsc 0 错误」** | 环境自带 7 处错 → **无法区分**「接入引入的错」与「环境固有的错」，验收判据失效 |
| 2 | **A4-00b 要拿签名覆盖率跟产物比对** | 工具链降级 → tree-shake 行为与原始不同 → **基线本身不可信**，比较结果无意义 |
| 3 | **O-5 已裁定「先修完才能判 M3」** | 不修环境，M3 永远判不出来 → A4 无法合法启动 |

#### 并行不空转的部分

| 任务 | 归属 | 时间 | 为什么能跟 B-5 并行 |
|---|---|---|---|
| **A4-P1 依赖梳理** | 全栈 | 10-15~10-16 | **纯静态分析**（读文件、列依赖符号、排接入顺序），不需要编译环境 |
| **B-7 发布脚本实现** | 后端 | 10-19~10-26 | 与 A4 链无耦合，但**必须早于 A5-01**（10-26）——留有 1 天缓冲，无冲突 |
| F-6~F-9 / U-5~U-8 | 前端 / UI | 10-15~10-23 | 完全独立，不进关键路径 |

#### 角色交接口（唯一的跨角色阻塞点）

> 本阶段关键路径**跨了两个角色**（后端 → 全栈），这是与第一、二阶段（全栈独占关键路径）的最大差别。
>
> **交接物**：B-5 完成时须交付「环境搭建文档 + 全仓 tsc 0 错误的证据」给全栈。
> **交接时点**：**2026-10-16 收工前**。
> **超时处置**：若 10-16 未交付，全栈按 P3-R1 降级口径自行接手环境修复，后端转为辅助。
