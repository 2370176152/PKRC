> **你的任务本质**：把「散落的 pointerdown 回调 + 被强制常驻的移动端虚拟手柄」重构为**统一、可配置、可禁用的交互层**。

## 一、问题根因（必须先理解，否则会做错方向）

> 现有鼠标支持不是「设计出来的交互层」，而是「在键盘-only 的 UI 上，逐场景外挂的一堆 `pointerdown` 回调 + 一套被强制常驻显示的移动端虚拟手柄」。

### 两条并存但不统一的实现路径

**路径 1：DOM 层 —— 虚拟手柄常驻**

- 位置：`game/server/dist/index.html` 的 `#touchControls`
- 链路：`touchstart`/`touchend` → `touchButtonDown/Up()` → `simulateKeyboardEvent()` → `emit("input_down", {isTouch:!0})`
- **缺陷**：
  1. `bindKey` 只绑 `touchstart`/`touchend`，**没有 `mousedown`/`mouseup`** → 桌面鼠标点击"按钮看得见、点不动"
  2. 常驻手柄遮挡画面（1280×800 尤其严重）
  3. **语义失真**：恒传 `isTouch:true` → `detectInputMethod()` 把 `scene.inputMethod` 判成 `"touch"` → 桌面端被错判为移动端

**路径 2：Canvas 层 —— 30+ 处散落的 Zone + pointerdown**

形态高度一致：

```js
const L = E.add.zone(x, y, w, h).setOrigin(0,0).setInteractive({useHandCursor:!0});
L.on("pointerdown", () => this.onXxxPointer(arg));
```

按下后**直接调用 UI handler 的私有方法**，或直接调 `processInput(w.CANCEL)`。

**绕过点**：绕过 `UiInputs` 的按键映射、模式白名单、`disableMenu`、`pendingPrompt` 判定、振动反馈、音效、`inputMethod` 标记。

### 必须解耦的 7 个耦合点

| # | 耦合 | 说明 |
|---|---|---|
| C1 | Zone 几何与 UI 布局硬编码 | 如 `zone(272,-172,44,14)`——坐标随布局变动即失效 |
| C2 | 命中区与渲染对象分离 | 透明 Zone 与真实文本/精灵无绑定，换行或缩放后错位 |
| C3 | 交互逻辑写在 handler 内 | 每个 handler 自带 `onXxxPointer`，无法统一开关/日志/禁用 |
| C4 | 守卫逻辑三份实现 | `pointerReady()` 三种变体 |
| C5 | 设备类型谎报 | 路径1 恒传 `isTouch:true` |
| C6 | 手势只认触摸 | `onSwipe*` 硬判 `s.wasTouch`，鼠标被排除 |
| C7 | 无统一禁用态 | 禁用元素没有统一 `enabled=false` 屏蔽，`setAlpha(.45)` 只是视觉 |

### 散落的配套机制（每个 UI 各写一份，互不一致）

| 机制 | 证据 | 问题 |
|---|---|---|
| 可用性守卫 | `pointerReady()` 三种变体 | 判定口径不统一 |
| 按键防抖 | `new ZO` + `keyGuard.arm()`（10 处）/ `isBlocked()`（6 处） | 无法全局协调 |
| 滚轮 | `bindWheel(s){s.on("wheel",...scrollBy(...))}` | 无节流、无 deltaMode 归一、无惯性 |
| 拖拽 | `startDrag`/`onDragMove`/`onDragEnd` + `dragPointerId` | 无"点击 vs 拖拽"阈值判定 |
| 滑动关闭 | `onSwipeStart/End`：`if(!s.wasTouch...)return`；阈值 `A<=-130&&Math.abs(A)>Math.abs(a)*1.5` | 仅触摸生效 |
| 悬停 | `addInteractionHoverEffect`：`setTint(12303291)` | 仅模态按钮有 |
| 焦点态 | `setFocus(s){return this.focusFrame.setVisible(s)}` | 焦点框仍由键盘光标驱动 |

### 四条核心设计原则

1. **语义分层**：鼠标事件 → **交互语义**（`activate` / `cycle` / `scroll` / `drag` / `context`）→ **Button 语义**（`UP/DOWN/.../CANCEL`）→ `ui.processInput()`。**终点与原版键盘链路汇合**，因此不破坏任何既有行为。
2. **声明式注册**：场景适配器只声明"哪里可点、点了做什么"，几何由**渲染对象派生**（解决 C1/C2）。
3. **单入口仲裁**：所有语义动作先过 `input-arbiter`，再进 UI（解决 C3/C4/C5）。
4. **配置驱动**：阈值、防抖、启用开关全在 `input-config.json`，改配置不改代码。

## 三、数据结构契约（必须逐字实现）

### 3.1 可交互元素模型

```ts
interface InteractionElement {
  id: string;                    // 稳定标识，如 "party.slot.2"
  scene: UiMode;                 // 归属场景（用于自动启用/禁用）
  target: () => Phaser.GameObjects.GameObject;  // 绑定真实渲染对象（非独立 Zone）
  hitArea?: {                    // 可选：命中区相对 target 的扩展（padding）
    expandX?: number; expandY?: number;
  };
  enabled?: () => boolean;       // 禁用判定（缺省 = target.visible && scene 匹配）
  onActivate?: ActionSpec;       // 左键点击
  onContext?:  ActionSpec;       // 右键
  onWheel?:    { step: number; throttleMs?: number };  // 滚轮翻页
  draggable?:  { axis?: "y" | "x"; onDragEnd?: ActionSpec };
  hoverable?:  { tint?: number; focusFrame?: boolean };
  focusIndex?: number;           // 与键盘光标位置的映射（点击后同步焦点）
  priority?: number;             // 重叠区域的命中优先级
}
```

### 3.2 动作规格（语义 → Button 的桥）

```ts
type ActionSpec =
  | { kind: "button"; button: Button; guard?: "ui" | "direct" }  // 走 ui.processInput
  | { kind: "cursor"; index: number; then?: Button }             // 先 setCursor 再提交
  | { kind: "scroll"; delta: number }
  | { kind: "custom"; fn: string }                               // 注册到 action-registry 的具名动作
```

> **`kind:"button"` 是默认与推荐路径**——鼠标最终产生与原键盘相同的 `Button` 语义，从而复用 `UiInputs` 的模式白名单、音效、振动、`disableMenu` 等既有判定，避免重复实现。

## 四、S2 输入层核心（第一批交付）

### 4.1 任务 2.1：`pointer-manager.js`

**要点**：
- 统一注册 `pointerdown` / `pointerup` / `pointermove` / `wheel` / `contextmenu`
- **不使用** DOM `click`（Phaser 已抽象 pointer，避免与 canvas 坐标错位）
- 所有坐标走 `scene.input.activePointer` 的**世界坐标**，不经手 CSS 像素
- 监听 `pointerupoutside` + `pointerout` 双保险（拖拽态必定释放）
- 监听 `window.blur` / `document.visibilitychange` / `Phaser.Core.Events.BLUR` → 复位拖拽/pending 手势/hover/lastDevice/tint

### 4.2 任务 2.2：`gesture-resolver.js`（可在 S0 前先做 + 单测）

**纯逻辑，无 Phaser 依赖**——这是你可以**立即开工**的部分。

判定规则：

| 场景 | 判据 |
|---|---|
| 点击 | `pointerup` 且 时长 ≤ `clickMaxDurationMs`(250) 且 位移 ≤ `dragThresholdPx`(8) |
| 拖拽 | `pointermove` 位移 > `dragThresholdPx`(8) → `pointerup` 不再派发 click |
| 长按 | 时长 > `clickMaxDurationMs` 且未达 `longPressMs` → 降级为拖拽/长按 |
| 连点防抖 | `lastClickAt` 在 `doubleClickDebounceMs`(180) 内的二次点击被吸收（白名单元素除外） |
| 滚轮 | 归一化 `deltaMode`（`DOM_DELTA_LINE/PAGE` → 像素），`wheelThrottleMs`(60) 节流 |
| 多按钮 | 仅响应 `button===0`（左键）与 `button===2`（右键）；中键忽略；`contextmenu` 默认 `preventDefault`，仅配置允许处派发 |

**要求**：`gesture-resolver` 必须能在 Node 里跑单测（导出纯函数，不 import Phaser）。

### 4.3 任务 2.3：`input-arbiter.js`

| 机制 | 设计 |
|---|---|
| 设备标记 | 扩展 `scene.inputMethod`：新增 `"mouse"`，与 `keyboard/touch/gamepad` 同级；维护 `lastDevice` |
| 同帧去重 | 记录 `(button, frameId)`，重复即丢弃 |
| 切换冷却 | 键鼠切换有 `switchDebounceMs`(120) 冷却 |
| 键盘不被抢占 | 鼠标**只**在 `pointerdown/up` 成功配对且未超阈值时派发一次动作；`pointermove` 仅更新 hover |
| 按住不放 | 统一按"单击"处理（不模拟长按连发），避免与键盘 `keydown` 重复连发语义冲突 |

### 4.4 任务 2.4：`legacy-bridge.js`

**职责**：把语义动作翻译为 `ui.processInput(Button)`，并同步 `setCursor`。

**关键**：复用原版既有判定，**不另开通道**：
- `ui.overlayActive` → overlay 激活时除自身外全部禁用
- `globalScene.disableMenu` → 鼠标触发 MENU 语义时同样生效
- `pendingPrompt` → 战斗指令时序保护

### 4.5 任务 2.5：撤销虚拟手柄常驻（跨角色）

| 事项 | 归属 |
|---|---|
| 移除 `#touchControls{...!important}`（3 条声明） | **UI 设计师** |
| 外置 `pkrc.css` 的 `@media (pointer:fine)` 隐藏规则 | **UI 设计师** |
| `virtualPad.mode` 行为开关（`auto`/`force-on`/`force-off`） | **你** |

**你必须实现**：读 `input-config.json` 的 `virtualPad`，按 `pointer: fine` + 触摸能力判定，通过 JS 控制 `#touchControls` 的 class（不用 `!important` 硬覆盖）。

| # | 验收项 | 判据 |

## 五、S3 场景适配器全量 + S4 新增系统

> **🔼 追加要求（2026-10-13 · 见 `07-源码化优先级重估与分工重组.md` §4.1）**
>
> 因源码化优先级调整为「长期可延后」，`pkrc/**` 成为**更长期的载体**。请遵守三条**可迁移性**要求（成本几乎为零，但长期收益复利）：
>
> | 要求 | 说明 |
> |---|---|
> | **① 模块可独立迁移** | 每个适配器不得依赖外置层的私有约定；单独搬走也能工作 |
> | **② 接口语义与上游概念对齐** | 用 `scene.ui.mode` 这类上游概念，**不造自造名词** |
> | **③ 只用上游公开 API 等价物** | 避免依赖产物内私有方法（如 `this.onXxxPointer`）与压缩变量名；若必须依赖，**登记为例外** |

| 3-F | 右键 | 已配置元素右键 → 触发 `onContext`，浏览器菜单不弹出 |
| 3-G | 新增系统 | 天赋/命座/解明/二游/PT 全部可鼠标操作，与键盘结果一致，无双触发 |
| 3-H | 回归 | 共用回归清单（见总览 §5） |

## 八、关键假设清单

1. **假设** 所有场景的交互入口都可归结为「设置光标索引 + 提交 Button」两步（`kind:"cursor"` + `kind:"button"`）——个别私有方法（如 `toggleTriplePassives`）需走 `kind:"custom"` 注册。
2. **假设** `scene.input.activePointer` 在世界坐标系下可直接用于命中判定（Phaser 3 标准行为）。
3. **假设** 30+ 处 pointerdown 中的 Zone 都可通过 `target()` 反向绑定到真实渲染对象——若某处 Zone 是纯透明命中区且无对应渲染对象，**登记为例外并保留原实现**。
4. **假设** `keyGuard` / `pointerReady` 等原守卫**保留不删**；仲裁层只做跨设备去重，不替代原守卫。

> 例外与假设必须在 `docs/input-layer.md` 中登记。
