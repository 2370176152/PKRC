## 四、🔴 首次运行即发现：**P0 启动阻断缺陷**

### 4.1 双产物对比结果（`--scenario boot --product both`）

| 项 | **A** modder 原产物 | **B** 自构建产物 |
|---|---|---|
| 画面就绪 | ✅ 3.1s（stdDev 77.6） | ❌ **30s 超时（纯黑）** |
| 未捕获异常 | **0** | **2** |
| 像素差异率 | — | **53.0%**（包围盒近乎全屏） |

### 4.2 根因（已定位到行）

**`src/data/systems/` 里有 24 处 `declare function/const` 占位 —— 零 emit ⇒ 调用即 `ReferenceError`。**
`talent-system.ts:97` 的 `declare function safeT(...)` 在 **boot 阶段**被调用 ⇒ 客户端黑屏。

**为什么此前全绿**：`tsc` 0 错、`vite build` EXIT=0、签名覆盖率反而把 `safeT` 计为「命中」——
**静态 gate 对这类缺陷一律失明**。

> 📄 完整清单（24 项 · file:line · 产物短名 · A 版参考实现）：`docs/sourcemigration/A4-00b-前置-24处declare悬空引用清单.md`
> 📄 证据包：`tools/walkthrough/evidence/boot-A-B/`

**⇒ 这印证了 O-9b「双产物对比」的价值**：最可靠的期望画面就是原版跑出来的画面 ——
A 能进游戏、B 黑屏，「B 有 A 没有的缺陷」是**机器可判的硬事实**，不需要人眼看。

## 五、技术路线与关键决策

| 决策 | 取舍 |
|---|---|
| **自写 CDP 客户端**（Node 22 原生 `WebSocket`） | 项目无包管理器；playwright/puppeteer 装不进来。**零依赖**是硬约束下的唯一解 |
| **驱动系统 Edge**（`--headless=new`） | 沙箱实测可 spawn 浏览器（**不含 node→node spawn**，那条路仍被封） |
| **调试端口用 `0`** | 内核自选 ⇒ A/B **并跑不抢端口**（P4-R10 需要的隔离） |
| **静态服务器支持叠加根** | A 版资源不完整；叠加 B 的资源层 ⇒ **免拷贝 825MB**，且两版共享同一份资源、差异只来自 `assets/` |
| **就绪判据 = canvas ∧ 帧方差 ∧ 连续 2 帧** | 早期只有触摸控件 DOM（~340ms）会误判为就绪 ⇒ 必须查 canvas |
| **`settle`：连续两帧变化率 ≤2% 才截图** | splash 过渡帧截图会让 A/B 对比失去意义 |
| **PNG 自解码 + 自 diff** | 判据②要求「差异率 + 热区」；Node 内置 `zlib` 足够 |
| **Windows 启动器存根不加区分** | `msedge.exe` 会立刻退出（code 0）而真实浏览器在子进程 ⇒ 就绪只看 `DevToolsActivePort`，清理按 profile 匹配 |

## 九、已知边界

- **不伪造通过**：产物跑不起来就如实报「未就绪」（B 版当前即如此），不粉饰。
- **像素 diff 有噪声**：默认阈值 12 滤除抗锯齿/字体 hinting；超阈 = 待裁定候选，**不等于缺陷**。
- **不替代人工**：项目所有者保留**全量证据包复核权**；AI 视觉审阅**不得单独作通过依据**。
- **未覆盖**：GPU/WebGL 差异、音频输出、真实网络联机 —— 本环境只覆盖「本地单机走查」。
