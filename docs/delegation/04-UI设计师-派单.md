## 二、设计规范（Token 体系 — 你的核心产出）

### 2.1 字号层级（7 级，以原版既有使用为基线收敛）

| Token | 值(px) | 用途 | 对齐来源 |
|---|---|---|---|
| `display` | 128 | 标题 / 大字号演出 | — |
| `title` | 66 | 界面标题 | ✅ `Je.title` |
| `heading` | 60 | 区块标题 | ✅ `Je.row` |
| `body` | 54 | 正文 | ✅ `Je.body` |
| `label` | 48 | 标签 / 次要文本 | ✅ `Je.small` |
| `caption` | 42 | 说明 / 提示 | ✅ `Je.tiny` |
| `micro` | 36 | 角标 / 极限压缩场景 | — |

> **收敛规则**：27 种取值 → 7 个 token；**禁止**再出现裸 `fontSize:"Npx"`。
> **设计要点**：5 个 token 直接对齐既有 `Je`，因此**大部分界面的视觉零变化**——只有 22 种"野生值"被吸附到最近 token。

**映射示例**（供 `apply-legacy.js` 使用）：

| 野生值 | 吸附到 | 偏差 |
|---|---|---|
| 26 / 30 / 32 / 34 / 35 | `micro` (36) | −10 ~ −1 |
| 38 / 40 | `caption` (42) | −4 ~ −2 |
| 44 / 45 / 48 / 50 | `label` (48) | −4 ~ +2 |
| 54 / 55 / 56 / 58 | `body` (54) | 0 ~ +4 |
| 60 / 64 / 65 | `heading` (60) | 0 ~ +5 |
| 66 / 70 / 72 / 76 / 80 | `title` (66) | 0 ~ +14 |
| 128 | `display` (128) | 0 |

> **你的设计判断**：`micro` 建议定为 36 而非 42，因为 26–35 区间有 5 种取值（野生值密度最高），需要足够的吸附余量。

## 四、落地路径（**不破坏现有渲染** — 这是本任务最关键的约束）

### 4.1 新增 `pkrc/theme/text-factory.js`

**包装原版文本创建函数**，所有**新增/重写**界面必须经它创建文本，自动应用 token。

```js
// 设计要求（接口交由前端/全栈消费）
export function createText(scene, x, y, content, opts = {}) {
  // opts.level: 'display'|'title'|'heading'|'body'|'label'|'caption'|'micro'
  // 自动: fontSize = token(level) * scaleFactor
  //       lineSpacing 由 lineHeight token 派生
  //       配色走 TextStyle 引用，禁止内联色值
  // 返回 Phaser.GameObjects.Text
}
```

### 4.2 对既有 108 处裸值：**运行时归一**（关键设计）

> **不逐个改 chunk**（会破坏补丁可维护性），改为**运行时归一**——外置层在文本对象创建后，把 `allowedLiterals` 白名单外的取值映射到最近 token。

**为什么这样做**：
- 若改 chunk，等于把 108 处改动 × 每次上游更新重做一遍（违反 R1）
- 运行时归一既统一视觉，又不动产物

**实现要点**（`apply-legacy.js`）：
- Hook Phaser 的文本创建路径（或在 scene 就绪后遍历已有 Text 对象）
- 对每个 Text：读 `style.fontSize` → 若不在 `allowedLiterals` → 映射到最近 token
- **映射必须保持"最近邻"**：避免 `54 → 66` 这种跳级（会明显改变布局）
- Hook 失败时**静默降级**（不抛错、不阻塞）

### 4.3 新增模式界面重构（S6 关联）

逐个把 **天赋 / 命座 / 解明 / 二游 / PT** 界面的文本创建改为经 `text-factory`：

| 改造项 | 从 | 到 |
|---|---|---|
| 字号 | 裸 `fontSize:"Npx"` | `opts.level` token |
| 配色 | 自造 `F.*` / 内联十六进制 | 引用原版 `TextStyle` |
| 间距 | 散落值 | `space.*` 标度 |
| 视觉组件 | 自造窗口/光标/滚动条 | 复用原版 `addWindow` / 光标组件 |
| 文案 | 内联中文 | `i18next.t('pkrc.xxx')` |

**目标**：实现"与原版一致的视觉语言"。

### 4.4 分辨率与缩放一致性

| 项 | 方案 |
|---|---|
| ScaleManager | 统一 `FIT` + `baseWidth:1920 / baseHeight:1080` + `dprAware`，避免 CSS 与 Canvas 两套缩放打架 |
| CSS | 复用既有 CSS 变量体系（`--controls-size: 10vh`、横屏 20vh、`@media (pointer: coarse)`） |
| 新增样式 | 一律用 `vh/rem` + 变量，**禁止新写固定 px** |
| 高 DPI | 校验 `window.devicePixelRatio` 与 `ScaleManager.zoom` 一致 |
