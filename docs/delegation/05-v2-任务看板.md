## 六、阻塞看板

> **🟢 2026-10-13 第一阶段实测更新（后端）**：§一 的 3 项阻塞**已实测全部解除**，A0 **不存在真实阻塞**。
> 详见 `docs/tech-stack-decision.md` §0（修正 §M-1/M-2/M-3）与 §1.2/§3.1。
>
> | # | 原判断 | 实测结论 |
> |---|---|---|
> | **BLOCK-1** | 便携 Node v16 vs 上游 Node 22 | ⚠️ **非阻塞**。便携 v16 **仅用于运行期服务**（实测 35 项测试全绿），构建期用系统 v22.22.2。上游 beta 现状实为 **v24.9.0**，应按锁定 commit 定版本 |
> | **BLOCK-2** | pnpm 未安装 | ✅ **可解**。系统 Node 22 自带 **corepack 0.34.6** → `corepack prepare pnpm@10.34.5 --activate`（无需 `npm -g`） |
> | **BLOCK-3** | clone 卡住，需换源/改完整 clone | ❌ **原判断有误**。**直连 GitHub 可用**；根因是 `--filter=blob:none` 的 promisor 按需拉取。方案：`--depth 1 --single-branch` → **21 MB / 数十秒**（实测） |
>
> **🔴 真正的新瓶颈**：不是 clone，而是 **A0-2 之后无人做 C-4（魔改点迁移清点）**。见 `tech-stack-decision.md` §2.4。
