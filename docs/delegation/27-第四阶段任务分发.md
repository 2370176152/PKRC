## 零、阶段定义

### 0.1 一句话目标

> **把第三阶段欠下的验证补完：M3 硬卡点归零 → 功能等价实测（M4）→ M5 正式达成。**

### 0.2 为什么第四阶段是「收口」而不是「开新线」

第三阶段结束时，项目处在一个**危险的位置**：

| 事实 | 后果 |
|---|---|
| 迁移完成度仅 **~58%** | 67 项 mod 新增未迁（已补 40）、20 处 patch 宿主未迁（已迁 12） |
| **M3 硬卡点未通过**（O-5 口径） | 地基未验收 |
| **A4-01/03/04 未做** | 功能等价**零验证** |
| **`dist/` 已切换**（A5-01 抢跑） | ⚠️ **未验证的产物已上线** |

**⇒ 若此时开 S6/S7/S8c（输入层/视觉/发布），等于在三重未验收的地基上盖楼。**

**故第四阶段只有一件事：把地基验证完。** 三条线在本阶段的工作**全部限定为"不依赖稳定地基的前置"**。

> **这是与前三阶段最大的差别**：前三阶段都能靠"并行供料"填满等待期；
> 本阶段**没有可并行推进的主线** —— 因为主线本身就是"验证地基"。

### 0.3 🔴 本阶段的首要障碍与解法：GUI 环境

| 任务 | 第三阶段的判断 | 本阶段处置 |
|---|---|---|
| **A4-01** 11 系统走查 | 「需运行 GUI 游戏，本会话无法执行」 | ✅ **可自动化** → 建 **F-10 自动化走查环境** |
| **A4-04** 全流程 + 键盘回归 | 同上 | ✅ **可半自动化**（脚本驱动 + 人工确认关键画面） |
| **A4-03** `.prsv` 存档往返 | 「需真实存档 + 游戏内导入导出」 | ⚠️ **原判断偏严** —— **改走 Node 沙盒**，字段级往返，**无需 GUI** |

**F-10 是本阶段的解锁项**：没有它，A4-01/A4-04 会再次空转一个阶段。

**技术路线（F-10）**：headless browser（Playwright/Puppeteer）加载本地服务上的构建产物 →
脚本化键鼠输入 → 截图 + 状态断言 → 产出可复核的走查证据包。

### 0.5 🔴 所有者决议（2026-10-16 · O-9 / O-10 已裁定）

#### O-9 裁定：**授权 F-10 自动化**

> **GUI 实测口径 = 走 `F-10` 自动化走查环境**（headless browser + 存档注入 + 截图/状态断言）。
> 不采用「项目所有者亲自跑游戏」作为主路径。

**连锁影响**：

| 项 | 变化 |
|---|---|
| A4-01 / A4-04 的证据形态 | **自动化证据（截图 + 状态断言 + 日志）为验收依据** |
| F-10 的地位 | 从「建议方案」升为**唯一授权路径** ⇒ **P4-R2 的严重性上调** |
| 人工边界（**默认，可被 O-9b 调整**） | 项目所有者**抽查**：每系统 ≥1 张关键截图；**不逐张确认** |

> ⚠️ **默认人工边界的说明**：全自动化容易退化为"脚本跑绿就算过"。设为"每系统 ≥1 张抽查"
> 是在**几乎不增加成本**的前提下保留人的判断。若你希望更严（如逐系统确认全部画面）或更松
> （完全信任自动化），回一句即改。

> 🔴 **O-9 带来的新风险**：既然自动化是**唯一授权路径**，一旦 F-10 建不起来，
> **不得自行降级**（如默默改成人工目测），必须**回报所有者**。见修订后的 P4-R2。
