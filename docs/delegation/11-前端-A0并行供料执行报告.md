## 三、🔴 F-2 的最重要发现（推翻 v1 的部分假设）

v1 派单断言：「`bindKey` 只绑 `touchstart`/`touchend`，**没有 `mousedown`/`mouseup`** → 桌面鼠标点不动」。

**实测结论**：
- ✅ **本地产物确实如此**（`skipPointerDown` / `preventDoubleTapZoom` 均为 **0 处**）
- ❌ **但上游 beta（2026-08）已经修复**：`src/touch-controls.ts` 的 `bindKey()` 现在已绑 `pointerdown`/`pointerup`，并带 `skipPointerDown` 防重逻辑

**由此修正的三条判断**：

| 问题 | 修正后结论 |
|---|---|
| 上游 canvas UI 有鼠标交互吗？ | **没有**。canvas 层交互 **100% 是改版外挂**，必须我们做 |
| 虚拟手柄要自己加鼠标支持吗？ | **不用**。上游已支持 → 应该是**迁移上游实现**，不是重写 |
| S6 工作量 | **可能显著小于** v1 估计的「占全项目 50%」—— 这是**降低后续预估风险**的关键信息 |
| 是否新增 `inputMethod="mouse"`？ | 需要，但上游 `detectInputMethod` 只认 `controller_type`，须走**扩展**而非替换 |

> ⚠️ 待 A0-2 锁定 commit 后必须复核：本地 `TouchControl` 对应上游哪个版本，以决定「迁上游」还是「自己补」。
