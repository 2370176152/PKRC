### 0.2 为什么必须先解死锁（本阶段唯一的真问题）

第四阶段"建好了 10 项能力、却一项验证都没做"，根因不是没时间：

```
O-5 裁定：M3 未过 ⇒ A4 一律不得启动
        ↓
M3 过 = (d) 类残差 = 0  ⇒  需迁完 507 个符号
        ↓
507 中的大头 = UI 组件 61 + tree-shake 202/210 的宿主都在 UI
        ↓
UI 迁移已连续两次失败（三十三/三十四批，均回滚）
        ↓
        A4 永远不启动  ⇒  M4/M5 永远不达成
```

**这个死锁在团队内部无法解开** —— 因为"放行 A4"这个动作，只有所有者能做。

> **请注意**：O-5 的裁定在第三阶段是**正确的**（防止"挂账"变成技术债温床）。
> 它只是在第四阶段遇到了"判据本身不可能达成"的情况。
> **判据的严格性必须与"能否达成"一起验证**，否则越严格越僵死。
