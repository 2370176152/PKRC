## 0. 一条贯穿全局的前提（所有人都必须记住）

**本仓库不含 TypeScript 源码。游戏本体是 Vite 构建产物**（`game/server/dist/`），一切魔改走「精确字符串补丁 + 外置 ESM 模块层」。

这决定了三条铁律：

| 铁律 | 内容 | 违反后果 |
|---|---|---|
| **R1** | **禁止直接改 `assets/*.js` 压缩产物**（除已登记的最小锚点补丁） | chunk 哈希一变全部补丁失效；产物不可重建，改坏无法修复 |
| **R2** | 所有新逻辑写成 `game/server/dist/pkrc/**` 下的独立 ESM 文件 | 无法单文件禁用、无法版本化 |
| **R3** | 任何改动必须可回退：注释 `index.html` 一行 script，或 `patch-game.py revert` | 一旦回退不了，整个改造无法交付 |

**目标架构（唯一合法形态）**：

```
game/server/dist/
├── index.html                 ← 仅新增 1 行 <script type="module" src="./pkrc/index.js">
├── assets/                    ← 原产物，除 1–3 条钩子补丁外【不改动】
└── pkrc/                      ← 【新增】外置模块层（有源码、独立版本化）
    ├── index.js               入口：等待运行时就绪 → 装配各模块
    ├── runtime-bridge.js      运行时桥接（消费钩子暴露的对象）
    ├── input/                 输入层（第二部分）
    ├── theme/                 视觉层（第三部分）
    ├── config/                JSON 配置（热配置）
    └── i18n/zh-CN/*.json      抽出的 1808 条文案
```

## 3. 协作契约（冻结接口，改动需全员评审）

### 3.1 运行时钩子契约（S0 产出，前端+UI 共同消费）

**全栈必须交付**：

```js
// 钩子补丁成功后，全局必须存在：
window.__PKRC__ = {
  scene: <globalScene>,      // 必填：Phaser 场景实例
  version: "0.1.0",          // 补丁版本
  ready: true                // 就绪标志
}
```

**已验证的稳定锚点**（全栈不得更换）：

```
inputMethod="keyboard"    inputMethod="touch"    inputMethod="gamepad"
```

在 `loading-scene-*.js` 中，`E === globalScene`（可观察到 `E.add.zone(...)`、`E.gameData.getEryouData()`、`E.ui.playSelect()`）。补丁在这三分支任一处后追加导出。

**消费方（前端 / UI）读取约定**：

```js
// 统一通过 runtime-bridge 获取，禁止直接读 window.__PKRC__
import { runtime } from '../runtime-bridge.js';
const scene = await runtime.whenReady();   // 未就绪时返回 null，调用方必须静默降级
```

**降级契约**：钩子缺失时，`runtime.whenReady()` 返回 `null`，所有外置模块必须**静默不启用**，绝不抛错、绝不阻塞游戏启动。

### 3.2 入口契约（S0 + S2 + S5 三方交叠点）

`pkrc/index.js` 的装配顺序（全栈定义，前端与 UI 只插不改）：

```js
// 顺序不可变：theme 必须先于 input 装配
// 理由：text-factory 需在 UI 创建文本对象前就绪；input 的 hover 反馈依赖 theme 的 tint token
1. theme/apply-legacy.js   （可选，按 theme-config.json 开关）
2. theme/tokens.js         （注入 CSS 变量 + 暴露 token 查询）
3. input/index.js          （装配交互层）
4. pkrc.debug（DevTools 诊断命名空间）
```

**命名空间约定**（避免与产物变量冲突，产物已压缩为单字母变量）：

| 前缀 | 归属 |
|---|---|
| `pkrc.input.*` | 前端 |
| `pkrc.theme.*` | UI 设计师 |
| `pkrc.runtime.*` | 全栈 |
| `pkrc.config.*` | 全栈（配置文件读取器） |

### 3.3 配置契约（三方共同遵守）

| 配置文件 | 归属 | 消费方 |
|---|---|---|
| `pkrc/config/input-config.json` | 前端 | 前端 |
| `pkrc/config/theme-config.json` | UI 设计师 | UI + 前端（hover tint 取值） |
| `pkrc/config/runtime-config.json` | 全栈 | 全栈（日志级别、调试开关） |

**规则**：配置文件一律 JSON（**不允许 JSONC 注释**——计划书中的 `jsonc` 只是示意图，实际产物必须是无注释合法 JSON，否则 `JSON.parse` 会炸）。

### 3.4 CSS 改动归属（前端 ↔ UI 的唯一边界）

`assets/index-57B56a0n.css` 中有 1 条改版注入的强制规则：

```css
#touchControls{display:block!important;opacity:1!important;pointer-events:auto!important}
```

| 事项 | 归属 | 说明 |
|---|---|---|
| **移除**这 3 条 `!important` | **UI 设计师** | 走补丁 + 外置 `pkrc.css` 双保险 |
| 兜底隐藏规则 `@media (pointer:fine){#touchControls{display:none!important}}` | **UI 设计师** | 写入外置 `pkrc.css` |
| 虚拟手柄的**行为开关**（`virtualPad.mode`） | **前端** | 读 `input-config.json` |

## 4. 谁阻塞谁（关键路径）

```
全栈 S0（钩子 + 骨架）
   │
   ├──→ 前端 S2/S3/S4  ──┐
   │                      ├──→ 联合回归（S2.10 + S3.2.6 共用清单）
   └──→ UI  S5/S6      ──┘
   
后端 S1（服务层）──┐
全栈 S1（启动器）──┴──→ S7（Electron 主进程）──→ 重新验证输入层
```

**关键路径**：**S0 → S2 → S3 → S4**（前端段最长）。全栈的 S0 必须在第一时间交付，否则前端与 UI 全线等待。

**并行窗口**：
- 后端 S1 服务层 + 全栈 S1 启动器 → 可与 S0 并行（不同文件）
- UI S5 的 **Token 定义部分** → 可在 S0 前完成（纯设计，不依赖运行时）
- 前端 S2 的 **gesture-resolver 纯逻辑** → 可在 S0 前完成（可在 Node 里单测）

## 7. 风险与责任映射

| 风险 | 等级 | 主责角色 | 应对 |
|---|---|---|---|
| R1 chunk 更新致钩子锚点失效 | 高 | **全栈** | 锚点选语义稳定处；外置层"未就绪即静默降级"；启动前跑 `patch-game.py list` |
| R2 外置层与旧 pointerdown 双触发 | 中 | **前端** | 灰度期 `priority` + 同帧去重；验证通过后再逐场景删旧实现 |
| R3 隐藏虚拟手柄影响触屏用户 | 中 | **UI + 前端** | `pointer: coarse` + 触摸能力判定；配置可强制恢复 |
| R4 字号归一改变既有界面观感 | 中 | **UI** | 白名单例外登记 + 逐屏走查 + `scaleFactor` 回退 |
| R5 1808 条文案抽取工作量被低估 | 中 | **UI** | 分批（先通用后系统），每批独立验证 |
| R6 换 Electron 壳影响存档路径 | 高 | **全栈 + 后端** | 换壳前导出全量存档备份并验证导入 |
| R7 全局 `taskkill /IM node.exe` 误杀 | 中 | **全栈** | 改为 `/T /PID` + 父子进程树 |
| R8 无源码导致长期不可维护 | 高（长期） | **后端** | S8 源码化准备；本次改造不加剧（新增代码全部有源码） |
