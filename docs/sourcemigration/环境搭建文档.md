## 二、根因（7 处 = 2 类）

### 类别 A：`vite.config.ts` ×3 —— 工具链被人为降级

锚点树的 `vite.config.ts` 是**上游原版**（面向 vite 8 / rolldown）：

```ts
build: {
  minify: "oxc",              // vite 8 的 oxc 压缩器
  rolldownOptions: { ... },   // rolldown 专用选项
},
resolve: {
  tsconfigPaths: true,        // vite 8 原生 tsconfig paths
},
```

但 **A1 构建复现（2026-10-13）**把它降级以匹配 modder 产物的 rollup 签名：

```diff
  "vite": "^8.0.10",              →  "vite": "^7.3.1",
                                   +  "vite-tsconfig-paths": "6.1.1",
```

→ vite 7 的类型不认识 `minify:"oxc"` / `rolldownOptions` / `resolve.tsconfigPaths`，`tsc` 报 3 处错。

> **关键证据**：上游 `90df65097b6d` 的 `package.json` 声明的是 **`vite: "^8.0.10"`**，
> `pnpm-lock.yaml` 精确锁 **`vite@8.0.10`**。
> 且 `vite.config.ts.v8bak` 与 `vite.config.ts` **逐字节相同**（3064 B）——
> 说明该配置本就是 v8 的，降级是外部施加的。

### 类别 B：`pokemon-sprite.test.ts` ×4 —— `assets/` 子模块未初始化

```
TS2307  Cannot find module '.../assets/images/pokemon/variant/_masterlist.json'
TS2307  Cannot find module '.../assets/images/pokemon/variant/_exp_masterlist.json'
TS2578  Unused '@ts-expect-error' directive  ×2
```

模块解析不到 → `_masterlist` 退化为 `any` → `delete masterlist.female` 不再报错 → `@ts-expect-error` 变成「未使用」。

> **全代码库只有这一处**从 `assets/` 导入（`grep` 实测，2 个文件）。
> 即：**tsc 只需要这 2 个 JSON**，其余 700+ MB 资产与类型检查无关。

**实测结果**：① 8.2 s；② `EXIT=0` / **0 错误**；③ **28.3 s** / `EXIT=0` / 2707 模块。

### 4.1 ⚠️ 两个必须知道的注意事项

**(a) `assets/` 目录必须存在（哪怕为空）**

原生 `vite.config.ts` 挂的 `minify-public-json-files` 插件会执行：

```ts
const assetsDir = path.resolve("./assets");
minifyJsonFiles(assetsDir, outputDir);      // ← fs.readdirSync：目录不存在会抛 ENOENT
```

`fs.readdirSync` 在目录**不存在**时抛异常（**存在但为空**则返回 `[]`，正常）。
→ **删掉 `assets/` 目录会直接让构建失败**。同理 `locales/` 必须存在（当前 1738 个 JSON）。

**(b) 不要在锚点树里裸跑 `pnpm install`（有副作用）**

锚点树是 **tarball 解压**，**没有 `.git`**。其 `postinstall`（`lefthook install`）会**向上找到 PKRC 仓库的 `.git`**，
把钩子装到**仓库根**——本次实测已发生并被清理（见 §七）。
→ 复现时若不需要钩子，建议用 **`pnpm install --frozen-lockfile --ignore-scripts`**。

## 七、副作用清理记录（如实汇报）

执行 `pnpm install` 时，锚点树的 `postinstall` 触发了 **lefthook**：

```
. postinstall$ lefthook install; git config --local fetch.recurseSubmodules true; ...
. postinstall: Added config: D:\Work\Pokemon\new\lefthook.yml
. postinstall: sync hooks: ✔️
```

**根因**：锚点树无 `.git`，lefthook **向上找到了 PKRC 仓库的 `.git`**，于是把钩子装到了**仓库根**。

**造成的污染（已全部清除）**：

| # | 污染 | 处置 |
|---|---|---|
| 1 | 仓库根新建 `lefthook.yml`（未跟踪文件） | ✅ 已删除 |
| 2 | `git config --local fetch.recurseSubmodules = true` | ✅ 已 unset |
| 3 | `git config --local blame.ignoreRevsFile = .git-blame-ignore-revs` | ✅ 已 unset |
| 4 | `.git/hooks/prepare-commit-msg`（**会影响今后每次提交**） | ✅ 已删除 |

**已核验**：`.git/hooks/` 只剩 `*.sample`；两条 local config 已不存在。
**教训**：在无 `.git` 的子目录里跑 `pnpm install` 有**跨仓库副作用**——建议加 `--ignore-scripts`。
