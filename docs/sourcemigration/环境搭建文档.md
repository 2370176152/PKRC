## 二、根因（7 处 = 2 类）

### 类别 A：`vite.config.ts` ×3 —— 工具链被人为降级

锚点树的 `vite.config.ts` 是**上游原版**（面向 vite 8 / rolldown）：

```ts
build: {
  minify: "oxc",              // vite 8 的 oxc 压缩器
  rolldownOptions: { ... },   // rolldown 专用选项
},
resolve: {
  tsconfigPaths: true,        // vite 8 原生 tsconfig paths
},
```

但 **A1 构建复现（2026-10-13）**把它降级以匹配 modder 产物的 rollup 签名：

```diff
  "vite": "^8.0.10",              →  "vite": "^7.3.1",
                                   +  "vite-tsconfig-paths": "6.1.1",
```

→ vite 7 的类型不认识 `minify:"oxc"` / `rolldownOptions` / `resolve.tsconfigPaths`，`tsc` 报 3 处错。

> **关键证据**：上游 `90df65097b6d` 的 `package.json` 声明的是 **`vite: "^8.0.10"`**，
> `pnpm-lock.yaml` 精确锁 **`vite@8.0.10`**。
> 且 `vite.config.ts.v8bak` 与 `vite.config.ts` **逐字节相同**（3064 B）——
> 说明该配置本就是 v8 的，降级是外部施加的。

### 类别 B：`pokemon-sprite.test.ts` ×4 —— `assets/` 子模块未初始化

```
TS2307  Cannot find module '.../assets/images/pokemon/variant/_masterlist.json'
TS2307  Cannot find module '.../assets/images/pokemon/variant/_exp_masterlist.json'
TS2578  Unused '@ts-expect-error' directive  ×2
```

模块解析不到 → `_masterlist` 退化为 `any` → `delete masterlist.female` 不再报错 → `@ts-expect-error` 变成「未使用」。

> **全代码库只有这一处**从 `assets/` 导入（`grep` 实测，2 个文件）。
> 即：**tsc 只需要这 2 个 JSON**，其余 700+ MB 资产与类型检查无关。

### 4.1 ⚠️ 两个必须知道的注意事项

**(a) `assets/` 目录必须存在（哪怕为空）**

原生 `vite.config.ts` 挂的 `minify-public-json-files` 插件会执行：

```ts
const assetsDir = path.resolve("./assets");
minifyJsonFiles(assetsDir, outputDir);      // ← fs.readdirSync：目录不存在会抛 ENOENT
```

`fs.readdirSync` 在目录**不存在**时抛异常（**存在但为空**则返回 `[]`，正常）。
→ **删掉 `assets/` 目录会直接让构建失败**。同理 `locales/` 必须存在（当前 1738 个 JSON）。

**(b) 不要在锚点树里裸跑 `pnpm install`（有副作用）**

锚点树是 **tarball 解压**，**没有 `.git`**。其 `postinstall`（`lefthook install`）会**向上找到 PKRC 仓库的 `.git`**，
把钩子装到**仓库根**——本次实测已发生并被清理（见 §七）。
→ 复现时若不需要钩子，建议用 **`pnpm install --frozen-lockfile --ignore-scripts`**。

## 十、B-6 离线构建环境快照与校验（2026-10-14）

> **任务**：第三阶段 **B-6 离线构建环境快照** —— 让构建可复现，不再依赖"当前这台机器"。
> **交付**：`docs/sourcemigration/构建环境快照.json`（入库）+ `tools/verify-env.cjs`（零依赖校验器）

### 10.1 为什么是「快照 + 校验器」而不是「备份 node_modules」

`node_modules` 有 4 万余文件、体积以 GB 计，**不适合入库**。但真正需要固化的是：

1. **依赖解析结果** → 已由 `pnpm-lock.yaml` 承载（精确锁定每个包与版本）
2. **工具链版本** → 需显式记录（vite/rolldown/typescript 的实际安装值）
3. **环境完整性** → 需一个**可机器校验**的判据（而不是"我记得要装什么"）

→ 因此入库的是**快照清单 + 校验器**：小、可读、可 `diff`、可在 CI 里跑。

### 10.2 快照内容

| 分组 | 内容 |
|---|---|
| `upstreamAnchor` | 上游 commit `90df65097b6d` + `package.json` / `pnpm-lock.yaml` 的**取回 URL**（可脱离本机重建） |
| `toolchain` | node `24.9.0` · pnpm `10.33.2` · vite `8.0.10` · rolldown `1.0.0-rc.17` · typescript `6.0.3` |
| `files` | 4 个关键文件的 SHA256（`package.json` / `pnpm-lock.yaml` / `vite.config.ts` / `tsconfig.json`） |
| `nodeModules` | `.pnpm` 包数 / 顶层条目数 |
| `nativeBindings` | rolldown 的 Windows 原生绑定的存在性 |
| `dirs` | `assets/` 与 `locales/` 的存在性 + JSON 文件数 |

### 10.3 校验器用法

```bash
cd /d/Work/Pokemon/new
export PATH="$PWD/.build-tools/node-v24.9.0-win-x64:$PATH"

node tools/verify-env.cjs               # 校验当前环境 vs 快照（EXIT 0/1）
node tools/verify-env.cjs --snapshot    # 重新生成快照（环境有意变更后才用）
node tools/verify-env.cjs --json        # 机器可读 + 完整采集结果
node tools/verify-env.cjs --anchor=<dir>  # 指定锚点树
```

**六项检查**：

| # | 检查 | 抓什么问题 |
|---|---|---|
| ① | 关键文件哈希 | 环境漂移的第一信号（如 `package.json` 被再次降级） |
| ② | 工具链版本 | vite/rolldown/typescript 被换掉 |
| ③ | `node_modules` 规模 | 依赖没装全 |
| ④ | **原生二进制** | rolldown 的 `.node` 绑定缺失 —— **`pnpm install` 不一定报错**（optionalDependencies 语义），但构建会在启动时崩 |
| ⑤ | **必需目录** | `assets/` `locales/` 被删 —— 构建**必挂 ENOENT**（见 §四.1a） |
| ⑥ | **回归护栏** | 降级配置被误搬回根目录 —— 会让 `tsc` 立刻报 TS2307（见 §三.3） |

> ④⑤⑥ 三项都是 **B-5 实际踩过的坑**，固化进校验器防止复发。

### 10.4 从零复现实测（B-6 验收 ③）

```bash
cd "$ANCHOR"
mv node_modules node_modules.bak          # 移走
pnpm install --frozen-lockfile --ignore-scripts   # 从零装
node node_modules/typescript/bin/tsc --noEmit     # 验类型
node node_modules/vite/bin/vite.js build          # 验构建
```

**实测结果**：

| 步骤 | 结果 |
|---|---|
| `pnpm install --frozen-lockfile --ignore-scripts` | ✅ **23.7 s**，全部包按 lockfile 落位 |
| `tsc --noEmit` | ✅ `EXIT=0`，**0 错误** |
| `vite build` | ✅ `EXIT=0`，**31.8 s**，2707 模块，1739 JSON |
| `node tools/verify-env.cjs` | ✅ `EXIT=0` |

### 10.5 负向验证（证明校验器真的会失败）

| 用例 | 期望 | 实测 |
|---|---|---|
| 指向一个造假锚点 | 失败 | ✅ **11 项未通过**（哈希不符 / 目录缺失 / 原生绑定缺失），`EXIT=1` |
| 把 `vite.config.a313.ts` 搬回根目录 | 失败 | ✅ **1 项未通过**（回归护栏命中），`EXIT=1` |
| 清理后复验 | 通过 | ✅ `EXIT=0` |

### 10.6 🔴 实测踩到的一个陷阱：`.pnpm` 的**孤儿包**

首次快照记录 `.pnpm` 包数 = **358**；从零重装后 = **346**。

**差 12 个的原因**：pnpm **默认不清理** `.pnpm` 里的孤儿包。
A1 降级时代留下的 `vite@7.3.1` / `vite-tsconfig-paths` 等条目一直躺在那里，
而 `pnpm install`（增量）只做增删链接、**不 prune** `.pnpm`。→ **358 是虚高的污染值，346 才是 lockfile 的忠实结果。**

**已据此调整校验语义**：

- **「当前 < 快照」→ 判失败**（依赖没装全，真问题）
- **「当前 > 快照」→ 只提示**（历史孤儿包，无害）

> 这条修正很重要：若按「等于才通过」判定，一台干净的机器反而会被判失败。

### 10.7 局限（如实说明）

| # | 局限 | 影响 |
|---|---|---|
| 1 | 复现测试用的是**已预热的 pnpm store**（`reused`/`added` 大多来自本地缓存） | 未验证**冷 store**（需联网下载）的路径。网络可用性风险见 §五.1 |
| 2 | 校验器用 `process.version` 取 node 版本，取的是**运行脚本的解释器** | 若用系统 Node 跑校验，node 版本项会提示不一致（属预期） |
| 3 | `node_modules` 内容未逐文件哈希 | 只校验包数与关键版本；**逐文件校验成本过高、收益低**（lockfile 已锁定解析结果） |

**冷 store 复现的验证建议**（若需要）：

```bash
# 用独立 store 目录，强制走网络（耗时长，视网络而定）
pnpm install --frozen-lockfile --ignore-scripts --store-dir=.tmp-store-b6
```

### 10.8 变更时的正确做法

| 场景 | 做法 |
|---|---|
| 只想让构建跑起来 | `pnpm install --frozen-lockfile --ignore-scripts`（**不要** `--snapshot`） |
| **有意**升级依赖 / 工具链 | 改 `package.json` → `pnpm install` 更新 lockfile →**同步跑 `--snapshot`** 更新基线 → 在提交信息里说明 |
| 校验失败 | 按脚本末尾的「常见修复」提示处理；**先查原因再改快照**，不要用 `--snapshot` 掩盖问题 |

## 十一、B-10 · 走查环境（F-10）与「新机器从零复现」总表（2026-10-16）

> 交付报告见 `docs/sourcemigration/B-10-环境快照迭代.md`。
> 本节是**可照着敲的 runbook**：从一台空机器走到「能构建 + 能走查」。

### 11.1 🔴 先记住：本项目同时存在**三个** Node，用途互不通用

这是新机器上最容易踩的坑 —— 用错 Node 不会报「版本不对」，只会**构建失败**或**走查空跑**。

| 用途 | 用什么 Node | 本机实测版本 | 语法上限 | 用错会怎样 |
|---|---|---|---|---|
| **运行期**（`server.cjs` 静态服务） | `shared/runtime/node.exe` | **16.16.0** | `game/server/**` 只能写 Node 16 语法 | 用了高版本语法 → 玩家侧启动即崩（而开发机**测不出来**） |
| **构建期**（`tsc` / `vite build`） | `.build-tools/node-v24.9.0-win-x64/node.exe` | **24.9.0** | 无限制 | 用 16 跑 vite 8 → 直接起不来 |
| **走查期**（`tools/walkthrough/**`） | PATH 上的 `node`（任意 **≥22**） | **22.22.2** | 需 `globalThis.WebSocket` / `fetch` | 用 Node 16 跑走查 → `WebSocket is not defined` |

> `shared/runtime/node.exe`（16.16.0）**绝不能**用来跑构建或走查。
> 走查之所以要求 ≥22：CDP 客户端用的是**内置** `WebSocket`（Node 22 起提供），
> 这是「零 npm 依赖」得以成立的前提（本项目没有包管理器，playwright/puppeteer 装不进来）。

### 11.2 走查环境的三个前置条件

| 条件 | 怎么满足 | 怎么自检 |
|---|---|---|
| 一个 Chromium 内核浏览器（Edge / Chrome） | 装 Edge 或 Chrome；位置不在默认路径时用 `PKRC_BROWSER=<exe 绝对路径>` | `node tools/verify-env.cjs --wt-only` |
| Node ≥ 22 且有 `WebSocket` / `fetch` | 装 Node LTS（≥22），或直接用构建期 Node 24 | 同上 |
| A / B 两个产物目录 | `game/server/dist.modder-backup-20261016`（A，O-9b 对比基准）+ `game/server/dist`（B，被测） | 同上。A 缺 → 只能跑单产物 |

> ⚠️ `PKRC_BROWSER` 指向**不存在**的文件时，`lib/browser.mjs` 会**静默回退**到系统默认浏览器。
> 后果：你以为在测 Chrome，实际测的是 Edge，证据包来源标签是错的。
> `verify-env --wt-only` 会把这种情况判为**失败**并顶出来。

### 11.3 从零复现 · 轨道 A：构建（锚点树）

```bash
# ① 取锚点树（无 git，用 codeload tarball；GitHub 未开放 allowAnySHA1InWant，不能 git fetch <sha>）
ANCHOR_SHA=90df65097b6df76f713e6bd108afa84499e8b993

# ② 取构建期 Node 24.9.0（win-x64）—— 解到 .build-tools/node-v24.9.0-win-x64/
#    https://nodejs.org/dist/v24.9.0/node-v24.9.0-win-x64.zip
# ③ 取 pnpm 10.33.2（package.json 的 packageManager 字段声明）
```

### 11.5 三个坑（都是踩过的，不是理论风险）

1. **裸跑 `pnpm install` 会污染 PKRC 仓库**。锚点树没有 `.git`，其 `postinstall` 的
   `lefthook install` 会**向上找到 PKRC 的 `.git`**，在仓库根建 `lefthook.yml`、
   改 local config、装 `.git/hooks/pre-commit`（影响**每次**提交）。
   → 一定加 **`--ignore-scripts`**。
2. **`assets/` 与 `locales/` 目录必须存在**（可为空）。`minify-public-json-files`
   插件用 `fs.readdirSync` 读它们，**目录不存在会抛 ENOENT 让构建失败**。
3. **Windows 上 `msedge.exe` / `chrome.exe` 是启动器存根**：
   `--version` 零输出（EXIT=0），`proc.kill()` 也杀不到真实浏览器。
   → 版本只能从 `Application/<x.y.z.w>/` **目录名**读；
   清理要按 `--user-data-dir` 匹配进程。

### 11.6 一键自检（两条轨道都覆盖）

```bash
<VERSION_DIR>/node tools/verify-env.cjs --wt-only # 只校验走查环境（证据机不必装锚点树）
```

> `<anchor 同级>/.build-tools/node-v24.9.0-win-x64/node.exe tools/verify-env.cjs --snapshot`

### 11.7 走查环境失效的常见症状对照

| 症状 | 根因 | 处置 |
|---|---|---|
| `WebSocket is not defined` | 用了 Node 16 跑走查 | 换 PATH 上的 Node ≥22 |
| `未找到 Chromium 内核浏览器` | 没装 Edge/Chrome，或装在非默认路径 | 装，或 `PKRC_BROWSER=<exe 路径>` |

| 构建报 `ENOENT ... assets` | `assets/` 目录不存在 | `mkdir -p assets`（见坑 2） |
