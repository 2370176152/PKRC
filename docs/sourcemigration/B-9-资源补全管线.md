## 二、为什么需要「合并管线」（事实链）

这条链子每一环都是实测的：

```
① 上游 vite.config.ts：publicDir: command === "serve" ? "assets" : false
   ⇒ build 模式**不**走 publicDir ⇒ `pnpm build` 只产 JS/CSS

② 真正把资产搬进 dist 的是 plugins/vite/vite-minify-json-plugin.ts
   （apply:"build" + enforce:"post"）：
       minifyJsonFiles(path.resolve("./assets"),  outputDir)            // → dist/**
       minifyJsonFiles(path.resolve("./locales"), outputDir+"/locales") // → dist/locales/**
   ⇒ **dist 的资产形态 = assets 子模块的形态**

③ 本地 assets 子模块是**降级项**（B-3 已登记：只拉了 2 个 masterlist）
   ⇒ 我们构建出的 dist 只含 assets/ + index.html + locales/ + images/(2 文件)
   ⇒ 其余 8 类资源必须由**外部资产源**合并进来   ← **这就是 B-9 存在的唯一理由**

④ 上游没有 dist 组装脚本（B-3 已确认）⇒ 组装必须我们自己做
```

## 三、资源类表（14 类，管线的契约）

`kind` 决定「这一类由谁提供」，是 `merge` 选源的**唯一**依据：

| # | 资源类 | kind | 类型 | 下限 | 说明 |
|---|---|---|---:|---|---|
| 1 | `assets` | **build** | dir | ≥3 文件 | JS/CSS，文件名带内容 hash → 只能来自构建 |
| 2 | `index.html` | **build** | file | ≥500 B | 入口页，引用带 hash 的 bundle |
| 3 | `locales` | **both** | dir | ≥100 文件 | 见 §五（**双源，默认取资产源**） |
| 4 | `images` | asset | dir | ≥1000 文件 | 贴图 / atlas / palette |
| 5 | `audio` | asset | dir | ≥100 文件 | BGM / 音效 |
| 6 | `battle-anims` | asset | dir | ≥10 文件 | 战斗动画 JSON |
| 7 | `fonts` | asset | dir | ≥2 文件 | 字体 |
| 8 | `manifest.webmanifest` | asset | file | — | PWA manifest |
| 9 | `logo128.png` | asset | file | — | PWA 图标 |
| 10 | `logo512.png` | asset | file | — | PWA 图标 |
| 11 | `starter-colors.json` | asset | file | — | 初始配色表 |
| 12 | `exp-sprites.json` | asset | file | — | 经验条精灵坐标 |
| 13 | `service-worker.js` | **mod** | file | — | 魔改自有 |
| 14 | `pkrc` | **mod** | dir | ≥1 文件 | 输入层配置 `pkrc/config/input-config.json` |

## 四、命令与用法

```bash
# ① 校验（A5-01b 的直接调用口）—— 14 类逐项 + 引用可达 + 零字节
node tools/asset-pipeline.cjs verify [--dist=game/server/dist]

# ② 清单（含关键文件 SHA256，可存档、可比对）
node tools/asset-pipeline.cjs manifest --dist=game/server/dist \
     --out=docs/sourcemigration/dist-manifest-baseline.json
node tools/asset-pipeline.cjs manifest --dist=<暂存> --compare=docs/sourcemigration/dist-manifest-baseline.json

# ③ 发布前组装（B-7 的组装步）：构建产物 + 资产源 → 暂存目录
node tools/asset-pipeline.cjs merge \
     --build-dir=<anchor>/dist --asset-source=game/server/dist \
     --to=game/server/.release-staging/dist.new --mode=replace --commit

# ④ 就地补全（A5-01b）：只补缺失，**从不覆盖、从不删除**
node tools/asset-pipeline.cjs merge --to=game/server/dist --mode=fill \
     --asset-source=<另一份含 images/audio/fonts/… 的目录> --commit
```

**两种模式的语义差别（这是本管线的核心安全设计）**：

| | `--mode=replace` | `--mode=fill` |
|---|---|---|
| 用途 | 发布前组装（B-7） | 就地补全（A5-01b） |
| 覆盖 | **删后拷**（`assets/` 带 hash，不删会残留旧 hash） | ❌ 从不覆盖 |
| 删除 | 删目标同名项 | ❌ 从不删除 |
| 幂等 | 否（重复跑=重复覆盖） | ✅ 是（第二次跑补 0 个） |
| 护栏 | 目标非空必须显式 `--force-replace` | 目标必须已存在 |
| 回滚 | 由 B-7 的暂存+原子切换保证 | 不需要（纯增量） |
| 参数写法 | `--k=v` 与 `--k v` 都支持 | 同左 |

**默认 dry-run**：不带 `--commit` 只打印计划。破坏性工具必须「显式确认」—— 与 B-3 `assemble` 一致。

## 五、🔴 `locales` 双源冲突（**必须提请 A4/A5 裁定**）

这一条不在 B-9 的原始验收项里，是**做管线时实测挖出来的**，且它会让 A5-01b 「资源 0 缺失」的判定**假通过**。

### 5.1 事实

`locales` 在「构建产物」与「资产源」两处**结构性不同**，且**两棵树都不完整**：

| 维度 | 构建产物（锚点 locales 子模块） | 资产源（mod 发行版） |
|---|---|---|
| 语言目录数 | **28** | **17** |
| 中文目录名 | `zh-Hans` / `zh-Hant` | `zh-CN` / `zh-TW` |
| 加泰罗尼亚语 | `ca` | `ca-ES` |
| `en` 命名空间文件 | 64 | 62 |
| `en` key 总数 | 6,413 | 5,048 |
| 独有命名空间 | `biomes.json` `event-text.json` `game-data.json` `pokemon-category.json` `ribbons.json` `trainers-common.json` | **`talent.json` `talent-codex.json` `talent-tag.json`**（魔改天赋系统） + `biome.json` |

### 5.2 谁对？—— 代码给答案

锚点 `src/i18n.ts` 的 `supportedLngs`（第 155~200 行）列的是：

```
"zh-Hans"  // Chinese Simplified
"zh-Hant"  // Chinese Traditional
"ca"       // Catalan
...
```

语言的设置项 `src/system/settings/settings-language.ts` 也是
`changeLocaleHandler("zh-Hans")` / `("zh-Hant")`。

**而自构建产物里的代码同样如此**（实测 bundle 中出现 `zh-Hans` 1 次 / `zh-Hant` 1 次，
**没有** `zh-CN`）。作为对照，modder 原产物 bundle 里是 `zh-CN` 2 次 / `zh-TW` 2 次。

### 5.3 后果（这是真回归，不是理论风险）

> 当前 `game/server/dist/`（A5-01 状态）= **自构建代码（要 `zh-Hans`）+ mod locales（只有 `zh-CN`）**。
> ⇒ 代码 `supportedLngs` 的 26 种语言里，**14 种在 dist 里根本没有目录**
> （`zh-Hans` `zh-Hant` `ca` `es-419` `eu` `gl` `hi` `id` `nb-NO` `pl` `sv` `uk` `vi` …），
> 且**中文目录名不在 `supportedLngs` 内** ⇒ 中文语言包加载不上。
>
> 这不是「文案新旧」，是**语言目录名对不上**。走查（A4-01）选择中文时会直接暴露。

### 5.4 冲突的三类性质（5499 处，抽样确认）

| 类 | 例子 | 性质 |
|---|---|---|
| ① 排版约定 | 上游把 `\n$`（换行+分页）统一为 `$` | 纯格式，数量最大 |
| ② 真实改写 | `battle.json#pokemonCaught`：anchor「太好了！捉到{{pokemonName}}了！」 vs mod「{{pokemonName}}被抓住了！」 | 文案变更 |
| ③ 键形变更 | 上游把扁平键 `desc_default` / `gen_1` 改成**嵌套对象** `descDefault` / `gen:{1:…}` | 不是冲突，是两边各有对方没有的 key |

> ③ 解释了为什么「共享命名空间内 mod 多出的 key」有 707（en）/ 968（zh）——
> 其中相当一部分是**上游改了键形**，不是 mod 新增。

### 5.5 B-9 的处置（不替使用者做决定，但把工具做好）

1. **默认不静默替换**：`--locales-from` 默认 `asset`（= 保持发行版现状），并在 `merge` 时**大声告警**（含上面这些数字）。
2. **提供正解**：`--locales-from=union` —— **基座用构建产物**（语言目录名对、上游文本新）
   + **overlay 用资产源**（补回魔改 key 与命名空间），语言目录名按 **声明的** `LOCALE_ALIAS` 归位
   （`zh-CN→zh-Hans`、`zh-TW→zh-Hant`、`ca-ES→ca`；只放实测确认的，不做猜测性映射）。
3. **冲突策略可切**：`--locale-conflict=overlay|base`，**默认 `overlay`（保留 mod 文本）**。
   理由与 O-9b 直接相关：O-9b 的判据是「以 modder 原产物为期望画面」，若让上游文案覆盖
   5499 条，A/B 对比会凭空多出海量文本差异，**把真正的迁移缺陷淹没在噪声里**。
4. **union 实测结果**（`--only=locales --locales-from=union --commit`）：

```
✅ locales 并集完成：28 语言 / 1349 文件
   基座侧独有 key 补入 61144 条；overlay（mod）侧独有 key 补入 628 条
   两侧同 key 不同值 5499 处 → 【保留 mod 文本】
   en     : 7203 keys（= 6413 anchor + 707 mod 独有 + 83 mod 命名空间）
   zh-Hans: 7424 keys（= 6371 anchor + 968 mod 独有 + 85 mod 命名空间）
   talent.json 存在 ✅   battle.json#pokemonCaught = "{{pokemonName}}被抓住了！"（mod 文本保留）✅
```

### 5.6 建议（交 A4/A5 裁定）

> **建议采用 `--locales-from=union`，并在 A4-01 走查里用中文界面重点核对一次。**
> 它同时解决「14 种语言无目录」与「魔改文案丢失」，且不动 mod 的现有文本。
> 若 A5 认为上游较新文案更正确，再显式加 `--locale-conflict=base`（那会**改变 5499 条文案**，需走查证据支撑）。
>
> ⚠️ 无论选哪种，**都不该维持现状** —— 现状是代码与资源不匹配。

## 七、与上下游的接口

| 下游 | 关系 | 怎么用 |
|---|---|---|
| **A5-01b** | 直接依赖方 | `verify`（判定）· `manifest --out=`（留档）· `merge --mode=fill --commit`（补全） |
| **B-7 发布脚本** | 复用组装步 | 进程内 `require` 本模块（**不 spawn**，规避沙箱 EBUSY）；或 `merge --mode=replace` 到暂存目录 |
| **B-3** | 本管线继承其 `verify` 的四项检查，并把 [1/6] 从 6 个目录改为 **14 类表驱动** | 旧 `assemble` 保留（未删，向后兼容） |
| **B-10** | 清单基线可作环境快照的一部分 | `docs/sourcemigration/dist-manifest-baseline.json` |

> **为什么把 `verify` 的 [1/6] 改成表驱动**：原来写死的 6 个目录会
> **漏检** `pkrc` / `logo*` / `manifest.webmanifest` / `starter-colors.json` /
> `exp-sprites.json` / `service-worker.js` —— 而这几个**恰恰是 A5-01 §2.4 限制 #1 点名要求「就位」的**。
> 一个漏检的校验器比没有校验器更危险（会给出虚假的「通过」）。
