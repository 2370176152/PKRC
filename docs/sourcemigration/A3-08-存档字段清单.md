## 0. 结论摘要

搜打撤的存档分**三层**，各层落点与生命周期不同：

| 层 | 落点 | 生命周期 | 字段数 |

## 4. 加密 / 序列化注意（`.prsv` 层）

- `.prsv` 为 **BlowFish 加密** 的存档；产物符号 `a`(generateKeystreamAndEncrypt) /
  `C`(BlowFish_Encrypt) / `d`(BlowFish_Decrypt) / `qo`(encrypt) / `FI`(decrypt)。
- **A4-03 往返校验**：解密 → 解析 → 重新序列化 → 加密，应逐字节等价
  （L1 上述「旧档兜底」差异除外）。
- ⚠️ `Map` 类型（L2 的 `ptSoudacheStartingItems` / `ptSoudachePendingSave.pokemonMap`）
  在序列化时**转为数组**（L3 #3），**不可直接 JSON 化** —— 这是最易踩的坑。

**守卫逻辑**（`getRetreatHistoryEntry` 之外的存档导入界面）：
```js
if (o && m.gameMode === 10 && !PT_MODE_ALLOW_IMPORT_OVERRIDE) {
  alert(`PT搜打撤模式的存档不允许导入！\n请使用游戏内的撤离功能保存PT。`);
```
