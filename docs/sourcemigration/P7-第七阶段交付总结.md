## 二、🔴 5 个 P0（全部只有真跑才现形，tsc / vite build 全绿）

| # | 报错 | 根因 | 修法 | 严重度 |
|---|---|---|---|---|
| 1 | `ReferenceError: safeT is not defined` | 悬空 `declare`，但 `TALENT_POOL` 在**模块求值期**调用它 | 实现产物 `es`（`i18next.t` + 空串回退） | 阻断启动 |
| 2 | `TypeError: FixedBattleConfig is not a constructor` | **循环导入** `battle → modifier → pt-soudache-system → title-phase → game-mode → fixed-battle-configs → battle` | ① `TitlePhase` 改 `pushNew("TitlePhase")`<br>② 守门员数据表拆到零副作用 `pt-guardian-data.ts` | 阻断启动 |
| 3 | `ReferenceError: createSpeciesPartyWeightModifiers is not defined` | 同 1，走**启动路径**（`initializeTalentSystem → …`） | talent 剩余 6 项 declare 全部实现（`KN`/`Rre`/`xNe`/`Lue`/`Dse`/`I0`） | 阻断启动 |
| **4** | **B 停在登录页**（非报错） | **构建 mode 错**：`vite build` 默认 `production` ⇒ `VITE_BYPASS_LOGIN=0` | 改用 `vite build --mode app` | 🔴 **最严重** |
| 5 | `ReferenceError: ii / Ht / $l / Yi is not defined` | 15 处 `extends <declare 短名>` 在**模块求值期**继承 | `ii` 换真实 `Phase`；其余 4 个（L3 未接线 UI 基类）用空类占位 | 阻断启动 |

### P0#4 为什么最严重

`vite build` 读 `.env.production`（`VITE_BYPASS_LOGIN=0`）⇒ 编译期 `bypassLogin=false` ⇒ 必须登录。
而 modder 原产物 A 是 `bypassLogin=true`。

**⇒ 此前所有走查（第五/六/七阶段）测的都是「登录页上点几下」。**
实证：修后产物内 `Log in or create an account` 由 1 → 0；截图显示 B 首次进入游戏欢迎页。

### P0#5 的一个陷阱

修 `ii` 时不能直接 `extends Phase` —— `Phase` 是 abstract，会强制实现 `phaseName`，
连带把 `this.session` / `this.repeatSlot` 等 mod 动态字段报成 **30+ 个 TS2339**。
正解：`import { Phase }` + `const ii: any = Phase;`（运行时真值，类型留 `any`）。

## 四、方法论沉淀

### 4.1 `declare` 悬空的 4 种爆炸形态

| 形态 | 触发时机 | 能否静态查出 |
|---|---|---|
| ① 模块求值期调用 | `import` 时 | ✅ AST 扫描（我写过 `scan-toplevel-declares-ast.cjs`） |
| ② 启动路径调用 | `initializeXxx()` 时 | ❌ 只能真跑 |
| ③ 循环导入致类未初始化 | `import` 时 | ✅ depcruise + BFS（先过滤 `type-only`） |
| **④ 出现在 `extends` 子句** | `import` 时 | ✅ AST 扫 heritageClauses（本轮才补上） |

> ⚠️ ④ 还有个坑：**只在代码路径可达时才暴露**。`production` mode 把 `EryouStartPhase` 摇掉了所以不报，
> 切 `app` mode 后立刻崩 ⇒ **换构建模式后必须重跑一轮启动实测**。

### 4.2 排查顺序（本轮血的教训）

> **「走查大面积 unproven / 产物未就绪」先怀疑环境，再怀疑 route。**
> 我第一轮直接去归因 route 缺证据，实际是游戏停在登录页。两者症状一样（stdDev 有变化、能截图）。

### 4.3 其它

- **判断「代码是否进 bundle」必须遍历全部 chunk**。只搜最大的 `loading-scene-*.js` 会得出反向结论
  （实际在 `battle-scene-*.js`）。
- **`--quiet` 会把走查输出全压掉**（含裁定分布）。批量跑不要加，或从 `evidence/*/result.json` 汇总。
- **`vite build` 不等于 `npm run build:app`** —— 用错 mode 测出来的全是假数据。
