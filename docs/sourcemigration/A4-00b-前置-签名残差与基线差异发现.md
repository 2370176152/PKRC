## 4. 🔴 A4-00b 前置分析：**基线差异**（本阶段最重要的发现）

### 4.1 方法

以 **A4-00b 判据 ④⑤ 的口径**做残差分类：
- 产物具名符号 = `game/server/dist/assets/*.js` 中 `l(短名,"原名")` 的第二个参数（**2,704 个**）
- 「命中」= 该名字在**原生构建产物** `dist/assets/*.js` 中以标识符出现
- 「未命中」再分两类：
  - **B 类**：锚点树 `src/` 中有该标识符 → 属 tree-shake / 惰性加载 / 分块差异
  - **A 类**：锚点树 `src/` 中**没有**该标识符 → **基线差异**

### 4.2 结果

| 分类 | 数量 | 占比 |
|---|---:|---:|
| ✅ 命中（构建含） | **1,539** | 56.92% |
| **B 类**：上游有 · 构建未含 | **11** | 0.41% |
| 🔴 **A 类：锚点树 `src/` 中不存在** | **1,154** | **42.7%** |

**B 类全部 11 个**（可定性）：
`ArenaTrapTag` / `SessionVersionConverter` / `SettingsVersionConverter` / `SystemVersionConverter` /
`currentWave` / `describe` / `getSpeciesFilterRandomPartyMemberFunc` / `hpFrame` / `onSelect` /
`playerField` / `usable` —— 均为 tree-shake / 惰性 / 分块差异。

**A 类抽样**（**这些名字看起来都是标准 PokéRogue 内容**）：
```
AirBalloonModifier      AssaultVestModifier     ChoiceBandModifier
ChoiceSpecsModifier     ChoiceScarfModifier     BlackSludgeModifier
DampRockModifier        BoosterEnergyModifier   ElectricSeedModifier
BlunderPolicyModifier   AwakeningStoneModifier  ClearWeatherAbAttr
ClearTerrainAbAttr      CelebrateAttr           DamageBoostAbAttr
DunsparceEvolutionCondition  BiomeEvolutionCondition  CaughtEvolutionCondition
（另有 CallingCard* / DianXin* / Eryou* / EnemyTalentManager / DynamicBalanceManager / ChengfengTag
  —— 这些**确属魔改**，其缺失是「迁移未接入」的正常现象）
```

### 4.3 关键核验（**已排除测量误差**）

| 核验 | 结果 |
|---|---|
| `AirBalloonModifier` 在 `src/` 中 | **不存在**（含近似名变体亦无） |
| `CHOICE_BAND` / `AIR_BALLOON` / `ASSAULT_VEST` / `AWAKENING_STONE` 标识符 | **全部不存在** |
| `ClearWeatherAbAttr` | 锚点树只有 **`PreLeaveFieldClearWeatherAbAttr`**（长名包含它 → grep 假阳性；**独立类不存在**） |
| `BattleScene` / `Pokemon` / `Move` / `Modifier` / `Phase` / `ArenaTag` | ✅ 均存在（故核心骨架一致） |

> 结论：**A 类不是测量误差**，是锚点树确实没有这些符号。

### 4.4 含义（**为什么这是项目级问题**）

派单 24 §0.4 裁定 A4-00b 的「达标」包含：

| 判据 | 本发现的影响 |
|---|---|
| ④ 核心上游符号（`BattleScene`/`Pokemon`/…）**100% 命中** | ✅ 可达成（骨架符号俱在） |
| ⑤ **11 个自研系统符号全部命中** | ✅ 可达成（接入锚点后） |
| ③ 残差中 tree-shake / 依赖噪声类**逐条已定性** | 🔴 **A 类 1,154 个无法归入「tree-shake」或「依赖噪声」** —— 它们是锚点树**没有**的东西 |
| ② 残差中「**迁移缺陷**」类 = 0 | 🔴 **A 类中除魔改外的那部分，既不是迁移缺陷也不是 tree-shake** → **口径缺口** |

**即：判据 ②③ 的三分类（迁移缺陷 / tree-shake / 依赖噪声）覆盖不了 A 类。**

### 4.5 🔴 决定性证据：**锚点树 ≠ 产物构建基座**

**证据链（三处独立交叉印证）**：

**① 产物有「逐件命名」的修饰器类，锚点树是「声明式 + 通用类」**

产物 `index-D3KKGO7Y.js` 中存在**修饰器类 barrel**：
```js
const eU = Object.freeze(Object.defineProperty({__proto__:null,
  get AddPokeballModifier(){return J_},
  get AddVoucherModifier(){return j_},
  get AirBalloonModifier(){return zd},        // ← 逐件命名类
  get AssaultVestModifier(){return mG},
  get AttackTypeBoosterModifier(){return _o},
  get AwakeningStoneModifier(){...},
  ...
}));
```

锚点树 `src/modifier/modifier-type.ts` 则是**声明式**（道具 → 复用通用类）：
```ts
SCOPE_LENS: () => new PokemonHeldItemModifierType(
  "modifierType:ModifierType.SCOPE_LENS", "scope_lens",
  (type, args) => new CritBoosterModifier(type, (args[0] as Pokemon).id, 1),  // 通用类
),
```

**② 锚点树全树（含 `locales/`）**：`AIR_BALLOON` / `CHOICE_BAND` / `ASSAULT_VEST` / `AWAKENING_STONE`
→ **全部不存在**（连 i18n key 都没有）。

**③ 类数量级**：锚点树 `modifier.ts` = **79 个 `export class`**；产物具名修饰器类**多于此**
（含 `AirBalloonModifier` 等一批锚点树没有的）。

> **结论**：产物包含**晚于 v1.11.22 的上游内容**，即
> **A0 定位的锚点树 commit 与产物实际构建基座不一致**（产物基座更新）。
>
> 这也解释了为什么 §4.2 的 A 类里，**大量名字是标准 PokéRogue 风格**而非魔改风格。

**⚠️ 这条与 A0 报告「锚点树 = 产物源码 + 7 条补丁」的前提相冲突。**
A3-04 的「976 招式数值逐字段一致」不足以证明版本同一（招式数值跨版本稳定）。

### 4.6 两条可能解释（**已由 §4.5 判定为 ①**）

| 解释 | 判定 |
|---|---|
| **① 锚点树 ≠ 产物基座（版本差异）** | ✅ **已证实**（§4.5 三处证据） |
| ~~② 产物含大量「上游风格」的魔改新增~~ | ❌ 不成立（连 `locales/` 都没有对应 key） |

> **后续动作**：需回 **A0** 重新定位锚点树 commit，或明确「以产物为准、以锚点树为起点」的补差策略。
