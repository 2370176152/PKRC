## 4. 坑③（附带发现）：规范勘误 E3 —— 收益倍率签名错

**问题**：A3-01 冻结的 `constellation-framework.ts` 把「财源」收益倍率的首参标为 `Pokemon`：
```ts
constellationGainMultiplier(pokemon: Pokemon, speciesId, data)
  → return choices[4] === pokemon.species.speciesId ? CONSTELLATION_GAIN_MULT : 1;
```
但产物 `LSe(n,s,i)` 的 `n` 是**收益项 key 字符串**（`"pt"` / `"money"` / `"ptSettle"`）：
```js
function LSe(n,s,i){ const A=sa(i,s); if(A<4)return 1; const a=i?.constellationChoices?.[s]??{};
  return vR(s,4,i)==="exclusive" ? (r0[s]?.gainMultiplier?.(n,A,a) ?? 1) : (a[4]===n ? aSe : 1); }
```
调用点：`j1(A, J1("pt", rg(), ptSoudacheData))` —— 首参直接是 `"pt"` 字符串。

**影响**：原实现 `choices[4] === pokemon.species.speciesId` **恒不成立** → 通用「财源」节点收益倍率恒为 1（**静默失效**）。

**处理（规范勘误 E3）**：`constellationGainMultiplier` / `partyConstellationGainMultiplier` /
`ConstellationExclusiveHooks.gainMultiplier` 首参统一改为 `gainKey: string`；登记于规范 §8.1。
