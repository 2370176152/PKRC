## 4. 🔴 关键风险：ERYOU 的 813 个无注释 `declare`

### 4.1 问题

`eryou-system.ts`（327）+ `eryou-ui.ts`（486）= **813 个占位无任何语义注释**：

```ts
declare let $ae: any;
declare let AEe: any;
declare let E: any;
```

这些是 **A3-11 脚本化提取**的副产物：提取器收集了提取体中的**全部自由标识符**并逐个 `declare`，
**没有**记录它们在产物中对应的上游符号。因此：
- **无法直接映射**到上游模块 → 不能一键转 import；
- 但**运行期必须**是真实绑定（`declare` 不产生运行时代码 → 原样运行会 `ReferenceError`）。

### 4.2 影响

| 维度 | 影响 |
|---|---|
| A4-00 工作量 | 813 / 994 = **82% 的占位**集中在这 2 个文件 |
| A4-00b 签名一致 | ④⑤ 判据（核心上游符号 100% + 11 系统符号全命中）**依赖 ERYOU 能真正编译进构建** |
| 工期 | 派单给 A4-00 的窗口是 10-16~10-19（3.5 天），**ERYOU 可能吃掉大半** |

### 4.3 两条处置路径（**需所有者/全栈决策**）

| 路径 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A（推荐）重新提取** | 用**带符号消解**的提取器重做 ERYOU：对每个自由标识符，回产物**追踪其绑定**（keepNames 反查 / 作用域分析），得到「产物短名 → 上游原名」，再生成 `import { 上游名 as 短名 }` | 中高（需重写提取器 + 逐名核对） | 低（可验证：tsc + 签名覆盖率） |
| **B 运行时兜底（临时）** | 保留 `declare`，另建一个 `eryou-runtime-deps.ts` 从**全局对象**取这些符号（产物把很多符号挂在 `window`/`globalThis` 上） | 低 | **高**：依赖全局污染、类型全 `any`、不符合"接入锚点"精神；**会让 A4-00 的「tsc 0 错」以假象通过** |

> **建议走路径 A**。路径 B 会把"接入锚点"做成"接入全局变量"，A4-01 走查与 A5 切换时必然爆雷。

**路径 A 的可行依据**：产物带 **keepNames**（`l(短名,"原名")`，2,724 个具名符号），
所以「短名 → 原名」在产物中是**可查的**；A3-11 的提取器只是**没做这一步**。
