### 2.1 三种状态的含义（**务必区分**）

| 状态 | 含义 |
|---|---|
| ✅ **已物理迁移** | 代码已**写入** `src/data/systems/*.ts`，`tsc` 通过，可直接被接入 |
| 🔵 **UI 层** | 产物中即为 UI Handler / 组件，**不属数据层**，归前端 UI 任务（S6/S7）实现 |
| 🟠 **归属已定（call-site 级）** | 产物中这些函数是**内联在调用点**的效果助手（如 `applyThornArmorCounter` 内联在 `Pokemon.damage`；`getIceAgeStatBoosts` 内联在天赋触发点）。**归属系统已明确**，但物理迁移时机在**「接入锚点」阶段**（与所属系统的触发点一起落位）—— 因为这些函数没有独立系统边界，单独迁出反而制造假耦合。 |

> **⚠️ 如实说明**：🟠 类**尚未物理落入迁移树**。它们**不是遗漏**（每条都有归属系统），
> 但**尚未成为可编译的代码**。这与 A3-06 的 `TALENT_TRIGGER_LOGS`、A3-09 的 P5X 守卫同类处理。
> 若要求「A2 全部锚点均已成代码」，则此项需在 A3-13 后**追加一轮 call-site 迁移**。
