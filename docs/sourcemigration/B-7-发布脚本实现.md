**一条命令就能发布**（默认 dry-run，加 `--commit` 才落盘）：

```bash
node tools/release.cjs publish --build-dir=<构建产物> --asset-dir=<资产源> [--commit]
node tools/release.cjs rollback (--to=<备份> | --last) [--commit]
node tools/release.cjs list [--sizes]
```

**为什么「发布」= 只替换 `game/server/dist/`**（B-4 已实测，本脚本建立其上）：

1. Electron 外壳是 Nativefier 打的包，`targetUrl` 硬编码 `http://localhost:8000/` ——
   它**不加载本地文件**，只发 HTTP；
2. 便携 Node 路径（`启动.vbs` / `start-game.bat` / `--serve-only`）与 Electron
   **共用** `server.cjs` + `game/server/dist/`；
3. ⇒ 换掉 `dist/`，两条路径同时生效，**无需分别发布**；
4. 上游 `vite build` **不产资产**（`publicDir: serve ? "assets" : false`）⇒
   新产物必然是「构建产物 + 资产源」的**合并**，这一步由 B-9 的管线提供。

## 二、五处实现决策（ADR）

### 决策 1 · 沿用方案 B（暂存 → 原子切换 → 备份）

- **备选**：A 原地覆盖（半成品会在窗口期直接暴露给玩家）／C 多版本目录 + 符号链接
  （Windows 上符号链接需要权限或开发者模式，收益不抵成本）。
- **选择**：B。三步都能独立回退，且切换只需要**两次 rename**（原子）。
- **代价**：发布期需要 `2× dist` 的磁盘峰值（暂存 + 备份）。已用**写入探测**在预检
  阶段实测（Node 16 没有 `fs.statfs`，见决策 3 的说明）。

### 决策 2 · 备份用 `rename` 而非 `copy`（`--backup-mode=move`，默认）

- **收益**：省掉一次 750 MB / 38k 文件的拷贝。B-9 实测同量级的 `cpSync` 约 **3m45s**
  （Windows 上 38k 次 `copyFileSync`），rename 是**瞬间**的。
- **代价**：备份根必须与 target **同卷**。预检里显式校验，跨卷时**报错并提示改用
  `--backup-mode=copy`**（不静默退化）。
- **安全性不变**：B-4 的「⑤ 原子切换 = 两次 rename」照旧 ——
  第一次 rename 同时完成「备份」与「挪走旧的」，第二次 rename 放上新的。

### 决策 3 · SHA256 清单默认 `critical` 而非 `full`（**这是量出来的，不是拍的**）

2026-10-16 在真实 `game/server/dist`（38,062 文件 / 756.9 MB）上实测：

| 模式 | 覆盖 | 条目数 | 耗时 |
|---|---|---|---|
| `critical`（默认） | 表里 `type:"file"` 的类 + `assets/**` + `pkrc/**` | 18 | **0.4 s** |
| `full` | 全量 | 38,062 | **167.9 s（2m48s）** |

`critical` 覆盖的是**体积小且不可再生**的部分：`index.html`、`assets/` 构建产物、
`manifest.webmanifest`、`logo*`、`starter-colors.json`、`exp-sprites.json`、
`service-worker.js`、`pkrc/` 手工配置。
大资产（`images` / `audio` / `battle-anims` / `fonts` / `locales`）由 `verifyDist`
用「文件数 + 字节数」判损伤 —— 为它们每次发布多等 2 分 48 秒不划算。
要全量审计： `--hash=full`。

> 范围由**资源类表**的 `sha256` 标记驱动（`assets` / `pkrc` 标了 `true`），
> 不在 `hashTree()` 里硬编码目录名 —— 否则新增资源类时清单会**静默漏掉**它。
> 一个漏检的清单比没有清单更危险。

### 决策 4 · 冒烟必须识别 `server.cjs` 的「200 兜底」（**测试驱动发现的修正**）

`game/server/server.cjs` 对**未命中路径**返回 `200 + {"ok":false,"message":"File not found"}`，
**不是 404**（这是前端依赖的**有意行为**，源码中有显著注释，不得改动）。

⇒ 如果冒烟只判「状态码 200」，缺失的 JS/CSS 会被**静默放过**，
⑧ 的自动回滚**永远触发不了**。冒烟因此显式识别该兜底响应，并把它记为「等价于缺失」。
新增用例：`smokeTest 直接调用：引用缺失必须判失败（不能被 200 兜底蒙混）`。

### 决策 5 · 步骤 ② 关掉 `runMergePlan` 的合并后自检

`runMergePlan` 自带「本次选中的类是否就位」的自检（`cmdMerge` 需要它）。
但发布流程里，**合格判定只应由步骤 ③ 的 `verifyDist` 做一次**。
两处各判一次会造成误导性双报：② 报「组装失败」，③ 根本没机会跑。
关掉后（`selfCheck: false`），**② 的失败只剩一种含义：某个拷贝真的抛错了**。
新参数默认 `true`，`cmdMerge` 行为完全不变（回归 36/36 通过）。

## 三、九步流程

| 步 | 动作 | 失败即 | 是否触碰 target |
|---|---|---|---|
| ① | 预检（参数 / 源与目标互斥 / 同卷 / 磁盘写入探测） | **F1** 中止 | 否 |
| ② | 组装 → 暂存 `dist.new`（复用 B-9 `planMerge` + `runMergePlan`） | **F2** 中止并清暂存 | 否 |
| ③ | 校验暂存（复用 B-9 `verifyDist`：14 类 + 引用可达 + 零字节） | **F3** 中止，**保留暂存供分析** | 否 |
| ④ | 备份（`rename`，= 第一次 rename） | **F4** 中止 | 原子，未被移动 |
| ④′ | 写 `SHA256SUMS`（失败只告警，不清单阻断发布） | 仅告警 | 否 |
| ⑤ | 原子切换（= 第二次 rename） | **F5** 尽力恢复 | 失败则把备份换回 |
| ⑥ | 清理中间态 | — | — |
| ⑦ | 冒烟：进程内起服务（端口 0）→ `GET /` → 逐条验 `index.html` 引用 | **F6** | 读 |
| ⑧ | 冒烟失败 → **自动回滚**（target→`dist.broken-<ts>`，备份→target） | 报「需人工介入」 | 是（回滚） |
| ⑨ | 收尾：按 `--keep` 清理旧备份 | 仅告警 | 否 |

**⑥ 在 `move` 方式下自然消失**（不存在 `target.old` 需要清理）—— 已在输出中注明。

## 四、六条失败路径（全覆盖，逐条有独立用例）

| # | 场景 | 期望 | 用例 |
|---|---|---|---|
| **F1** | 预检失败 | 中止（exit 2）、**不碰 target、不建暂存** | 15 个用例：缺参、源缺 `index.html`/`assets/`、源不存在、target 不存在/不像 dist、**源与 target 互斥**、**暂存/备份在 target 之内**、`--backup-mode`/`--hash`/`--keep` 非法 |
| **F2** | 组装抛错 | 中止（exit 1）、清掉本次暂存、不碰 target | `暂存无法写入（父路径是文件）`、`F2 与 F3 的分工` |
| **F3** | 校验失败 | 中止、**保留暂存**、不碰 target | `类不全`、`index.html 引用缺失被 verifyDist 拦下`、`--no-verify 显式告警` |
| **F4** | 第一次 rename 失败 | target **未被移动**（rename 原子）、现场完好 | 打桩注入 `EPERM`，断言只失败 1 次 |
| **F5** | 第二次 rename 失败 | 把备份 rename 回 target（尽力恢复） | 打桩注入 `EINVAL`，断言共 3 次 rename、`restored:true` |
| **F5b** | 连「恢复」也失败 | 明确报「**需要人工介入**」+ 给出旧产物位置 | 打桩注入 `EIO`×2，断言 `restoreError` 有值、旧产物仍在备份目录 |
| **F6** | 冒烟失败 | target→`dist.broken-<ts>`，备份→target | 用「引用一个不存在的 js」真实触发（非打桩） |

> **为什么 F4/F5 用打桩**：真实的 rename 失败（EPERM / 跨卷 / 被占用）无法在进程内
> 稳定复现，沙箱也禁止 spawn 子进程。打桩注入是**唯一**能确定性覆盖「rename 抛错后
> 现场是否完好」的办法。`release.cjs` 与测试 `require` 的是同一个 `fs` 模块对象，
> 故补丁必然生效。

## 五、与 B-9 的对接（验收 ④）

**复用，不是复制**：

| 发布步骤 | 复用的 B-9 函数 | 说明 |
|---|---|---|
| ② 组装 | `planMerge()` + `runMergePlan()` | **取源策略的唯一实现**，与 `merge` CLI 不可能漂移 |
| ③ 校验 | `verifyDist()` | 14 类表驱动 + 引用可达 + 零字节，与 `verify` CLI 同一判据 |
| ④′ 清单 | `RESOURCE_CLASSES` | critical 范围由表的 `sha256` 标记决定 |
| ⑦ 冒烟 | `server.cjs` 的 `startServer()` | **在产品服务上跑**，不是另写一个静态服务器 |

**为什么不 spawn 子进程**：沙箱 spawn 会 EBUSY；且进程内复用能保证
「`release.cjs` 调用的校验器」与「A5-01b 手动调用的校验器」**是同一份代码**。
这是 B-9 重构（抽出 `planMerge`/`runMergePlan`/`verifyDist` 三个纯函数）的直接目的。

**降级路径（不隐瞒）**：若 `express` 解析失败，冒烟退回内置**迷你静态服务器**，
并在结果里标 `servedBy: "mini"` + 一行说明「本次冒烟**未**走产品路径」。
用例 `happy path 走的是产品服务（server.cjs）` 专门守住这条 —— 实测 `servedBy=server.cjs`。

## 七、接口契约

### 7.1 目录布局与「什么会被删」

```
game/server/
├── dist/                                  ← 当前生效产物（target）
├── dist.modder-backup-20261016/           ← A5-01 切换时留的原始 mod 产物
│                                             ⚠️ **不受 --keep 管理，永不被自动删除**
├── backups/                               ← 备份根
│   ├── dist.20261016-173303/              ← 一次发布 = 一份（rename 而来）+ SHA256SUMS
│   └── dist.20261016-181245/
└── .release-staging/
    ├── dist.new/                          ← 组装暂存（成功发布后即被 rename 走）
    ├── dist.broken-<ts>/                  ← 冒烟失败留证
    └── dist.rollback-<ts>/                ← 手动回滚留证
```

**`--keep` 只删严格匹配 `/^dist\.\d{8}-\d{6}$/` 的目录**。绝不使用前缀/通配符匹配 ——
同目录下还有 `dist.modder-backup-*`（回滚依据）、`dist.broken-*`、`dist.rollback-*`
这类**不能碰**的目录。用例 `pruneBackups 绝不删除非本工具命名的目录` 守住这条。

### 7.2 `SHA256SUMS` 格式

```
# PKRC release backup
# created: 2026-10-16T09:33:03.123Z
# files: 18
# mode: critical
<64位hex>  <相对路径>
```

`#` 开头的行被 coreutils 忽略 ⇒ 可直接 `sha256sum -c SHA256SUMS` 核对。

### 7.3 报告 JSON（`--report=<file>`）

关键字段：`step`（`preflight` / `assemble` / `verify` / `backup` / `switch` / `smoke` /
`smoke-rollback` / `done` / `dry-run`）、`target`、`backupDir`、`sums`、`staged`、`smoke`、
`pruned`、`durationMs`、`hashMode`、`backupMode`、`verify`，外加 `at` / `command` / `argv` / `log`。
⇒ **失败也能落盘**：出问题时报告里直接有失败所在步骤与当时的完整日志。

## 九、遗留与边界（如实）

1. **dry-run 会写暂存目录**（`<target 同级>/.release-staging/dist.new`）。
   这是**有意设计**（先真组真校，再决定要不要动线上），但确实不是「零写入」。
   已在输出与本文档显式说明，避免有人误以为 dry-run 不动磁盘。
2. **冒烟不能替代 GUI 验证**。脚本只能证明「HTTP 层引用可达」，
   不能证明 Phaser 能过加载场景。发布完成后打印**人工确认清单**
   （`启动.vbs` 静默启动 / 游戏能进加载场景 / `targetUrl` 仍是 `localhost:8000`）。
3. **未在真实 756.9 MB 数据上跑完整 `publish --commit`**。
   真实规模已验证的部分：冒烟（§6.3）、`critical` 哈希（§6.3）、`spaceProbe`（§6.5）。
   未做的原因：会真的替换线上 `dist/`，而 `dist/` 目前仍挂 **A5-01 的「未验证」标注**，
   替换时机属于 A5-01b 的职责，不由 B-7 单方面决定。
   **风险**：步骤 ①②④⑤ 在真实数据上的耗时未被本报告实测。
   已有的旁证是 B-9 用同一套 `planMerge`/`runMergePlan` 在真实数据上跑通了
   14/14 合并（**3m45s**，瓶颈是 Windows 上 38k 次 `copyFileSync`）。
4. **`--backup-mode=move` 需要同卷**。跨卷时预检会**明确报错**（不静默退化）。
5. **`locales` 的双源冲突仍未裁定**（B-9 §五）。`publish` 默认
   `--locales-from` 继承 B-9 的保守选择（= 资产源）并原样转发告警。
   **这个选择会改变运行期内容，必须由 A4/A5 裁定并留走查证据**；
   要采用并集： `--locales-from=union`（基座=构建产物 + overlay=资产源）。
6. **`game/server/.release-staging/dist.new` 有约 349 MB 测试残留**（B-9 全量合并的产物）。
   它是本工具自己的暂存目录，下次 `publish` 会自己清掉，**无害**；
   但它是磁盘占用。**清理需授权**（不是我该单方面删的东西）。
7. **`--hash=full` 在真实 dist 上要 167.9 s**。若在 CI 里每次发布都跑，需知道这笔账。
8. **F5b（恢复也失败）后 target 不存在**。此时脚本会打印
   「需要人工介入」+ 备份目录的绝对路径。这是**有意的**：宁可停在一个明确、
   可人工修复的状态，也不去猜。人工修复动作只有一步：把备份目录 rename 成 `dist`。
