## 一、为什么需要分层判据

原始 M3 判据是「(d) 类残差 = 0」。实测这条路走不通：

```
(d) 类残差 = 507 个未迁符号
        ↓ 域分布（A3-补-41 实测）
Eryou 养成    92   ← 系统级
UI 组件类     61   ← 已两批失败（三十三/三十四批均回滚）
天赋/时代     36   ← 系统级
五行/特性     18
squad          7
P5X/守卫       2
其余（战斗/系统）≈291
```

**⇒ 若坚持「507 = 0」，M3 永远不成立，A4 永远不启动（第四阶段死锁）。**

分层判据的目的：**让 M3 可判定，同时不让未迁项"消失"**。

## 四、✅ L1-2 的口径：**已确认采用「行为口径」**

两种口径的后果差很多，**2026-10-17 经所有者确认采用「乙：行为口径」**：

| 口径 | 判据 | 工作量 | 后果 |
|---|---|---|---|
| **甲：符号口径** | 「11 系统的 (d) 类残差 = 0」 | 中 —— **迁进 `src/` 即算**，不必接宿主 | 🔴 **可能是假完整**：符号在 src 里但无人调用 ⇒ 运行时不生效 |
| **乙：行为口径**（**本草案采用**） | 「11 系统核心路径走查通过」 | 取决于走查发现多少问题 | 🟢 **是真完整**：可达 + 行为正确才算过 |

### 为什么本草案选「乙」

**这正是第四阶段 O-8 决议的教训**：
> 「可编译」≠「功能等价」 —— tsc 0 错 + build EXIT=0，但迁移完成度只有 ~58%。

同理：「符号在 src 里」≠「功能可用」。

**实证**：`A3-补-41` 明确记录 ——
> 「迁完规则函数**仍不会自动命中** —— 规则函数需**被调用**才进 bundle ⇒ 必须同时接宿主。
> 而 `getOrCreateProgress` / `levelUpCost` 的宿主正是**未接线的 `eryou-ui.ts`**
> ⇒ **单独迁规则函数收益仍为 0**。」

**⇒ 若用符号口径，把 Eryou 66 个规则函数迁进 `src/` 就能让 (d) 归零，
但它们运行时根本不会被调用 —— 这是标准的"假完整"。**

**⇒ 建议确认「乙：行为口径」，符号覆盖率降级为辅助指标。**

> ✅ **已确认（2026-10-17）**：采用乙。符号覆盖率（74.94%）保留为**趋势指标**，不作 M3 成立条件。
