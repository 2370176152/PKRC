## 7. 🔴 根因修正（关键）：**A3 从未迁移「mod 对上游文件的修改」**

§4 说「约 30 个入口钩子未接入」—— 进一步追查后，**真正的原因更根本**。

### 7.1 决定性证据

产物中 `MoveEffectPhase.start()`（`class M1`）包含 mod **新增/改写**的方法调用：

```js
start(){ if(super.start(), ..., this.recordEryouSpreadPrimaryTarget(),
        this.resolveRedirectTarget(), this.resolveCounterAttackTarget(),
        this.resolvePreMoveStatusEffects(), this.lapsePreMoveAndMoveTags(), ...) }
```

| 方法 | 产物（modder 发行） | 锚点树 `src/` |
|---|---|---|
| `recordEryouSpreadPrimaryTarget` | ✅ 出现 2 次 | ❌ **不存在** |
| `resolvePreMoveStatusEffects` | ✅ 出现 2 次 | ❌ **不存在** |
| `lapsePreMoveAndMoveTags` | ✅ 出现 2 次 | ❌ **不存在** |
| `resolveRedirectTarget` / `resolveCounterAttackTarget` | ✅ | 🟡 在 `move-phase.ts`（是否被 mod 改写待核） |

⇒ **mod 对上游类的「新增方法 + 插入调用」根本没有被迁移。**

### 7.2 为什么这解释了 325 项

```
mod 钩子函数（applyChiXinOnHit / applyNianLiOnMoveUse / settleP5XRoundEffects …）
  ← 本应由「上游被改写的调用点」调用
  ← 但那些改写点**没有迁移** ⇒ 钩子永远不被调用 ⇒ rolldown 摇掉
    ⇒ 其调用链上的全部辅助函数（198 项「内部辅助」）一并被摇掉
```

⇒ **325 项不是 325 个独立缺陷，而是「上游 patch 点缺失」的单一后果。**

### 7.3 性质判定（需 owner 裁决）

| 选项 | 理由 |
|---|---|
| **(d1) A4-00 范围内** | 325 项符号**确实**由 22 文件承载 |
| **(d2) A3 范围缺口**（**本报告倾向**） | 修复它需要迁移 **mod 对上游文件的 patch 点**，而这类内容**不在 A3 的 22 文件范围内** —— A3 只迁了「mod 新增文件」，未迁「mod 对上游的改动」 |

**证据支撑「范围认定有缺」**：A1.3 只识别出 **7 条 patch**（`A1.3 7/7 逐字命中`），
但实测上游改写点**远多于 7 条**（仅 `MoveEffectPhase` 一处就有 3 个 mod 方法）。

> **⇒ 建议把「上游 patch 点迁移」登记为 A3 范围遗漏的**第 4 类**（前三类为：(d2) 符号缺口 / 旧树过时类 / API 差异）。**
> 这比 §4 的「钩子未接入」更准确 —— 钩子清单只是**其结果**，patch 点清单才是**任务源**。
