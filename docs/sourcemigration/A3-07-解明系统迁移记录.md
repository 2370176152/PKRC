## 1. 解明体系结构（产物真相）

解明是「多角色共享一套招式 / 冷却 / 计数 / 共享加成」的体系：

```
                      ┌─────────────────────────────────────┐
   花名册 GO          │ MANAPHY · PHIONE · MELOETTA · MEW   │
   (产物 `GO`)        └─────────────────────────────────────┘
                                      │
        ┌─────────────────────────────┼──────────────────────────────┐
        ▼                             ▼                              ▼
  MANAPHY群                      MELOETTA                          MEW
  （缺省模块）              registerJiemingModule          registerJiemingModule
  技能 = wm（3 招）         技能 = 音律/旋律/悦动           技能 = 察觉/洞悉/植入
  冷却 = 内建回退           冷却 = meloettaEffectiveCooldown 冷却 = mewEffectiveCooldown
  计数 = 海之守护           计数 = 节拍                     计数 = 属性编织
        └─────────────────────────────┴──────────────────────────────┘
                                      │
                          jieming-system.ts（公共框架）
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
        JiemingResolvePhase（统一结算）      registerJiemingModule 注册表
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  jieming-anims.ts        skill.apply() → 各系统效果
  （演出动画占位）
```

> **关键事实**：产物中**只有 2 处** `fEe`（`registerJiemingModule`）调用 —— MELOETTA 与 MEW。
> MANAPHY群 **不注册**，走 `tL` 的兜底值 `wm`（海之守护三招）+ `Are` 的内建冷却回退。
> 迁移版用**提供者钩子** `setDefaultJiemingSkills()` 等价实现（避免 `jieming ↔ manaphy` 循环依赖）。

## 4. 坑① 解明设施收敛

**问题**：A3-05 把解明框架设施（`getJiemingPokemon` / `findJiemingSkill` / `JIEMING_SHIELD_TAG` / `JiemingResolvePhase` 等约 30 个导出）临时寄放在 `manaphy-system.ts`，导致：
- 文件职责错位（MANAPHY 文件里塞了全体系框架）；
- `MEW` 需从 `manaphy-system` 导入 `JIEMING_SHIELD_TAG`（语义上不该依赖 MANAPHY）；
- `registerSeaGuardJiemingModule` 的 `cooldown: (p,s) => effectiveCooldown(p,s)` 会**无限递归**（`effectiveCooldown` 又回调模块 `cooldown`）——tsc 抓不到的隐患。

**处理**：
- 新建 `jieming-system.ts` 承载全部解明公共设施（**单一实现点**：`grep "function jiemingNodeActive"` 仅 1 处）；
- `manaphy-system.ts` 保留 SEA_GUARD 专属逻辑 + 3 个内建招式，末尾以「deprecation shim」再导出被迁走的符号（保证 A3-05 既有引用不破）；
- `MEW` / `HEALER` / `MELOETTA` 改为直接从 `jieming-system` 导入；
- **修复递归**：MANAPHY 不再注册模块，改用 `setDefaultJiemingSkills(() => JIEMING_SKILLS)`（等价产物 `wm` 兜底）；
- **修复冷却回调签名**：模块 `cooldown(pokemon, skill)` 收**招式对象**（产物 `i.cooldown(n,s)`），MELOETTA/MEW 注册时改 `skill → skill.id`（原实现误收 `skillId: string`）。

**依赖方向（无环）**：`manaphy/meloetta/mew/healer → jieming → constellation-framework`。

## 5. 坑② codex `id` 字段（规范勘误 E1）

**问题**：产物 `hasJiemingConstellation`（`iN`）判定式为
```js
if (s === undefined || !ire(s)) return false;
const codex = HM(s);
if (codex 为空) return false;
if (!codex.some(entry => entry.id?.startsWith("jieming"))) return false;
return US(s, QEe, ...);
```
即**要求该物种的 codex 中存在 `id` 以 `"jieming"` 开头的条目**。实测产物中：

| 系统 | codex 变量 | 首条 `id` |
|---|---|---|
| MANAPHY群 | `mTe` | `id: Hw`（`"jieming"`）|
| MELOETTA | `$Se` | `id: Hw` |
| MEW | `gTe` | `id: Hw` |
| CALLINGCARD / DIANXIN / HEALER / CHIXIN / NIANLI | `PSe`/`Que`/`$ce`/`P1e`/`tPe` | **无 `id`** |

而 A3-01 冻结的 `ConstellationCodexEntry` 仅 `{name, description}`，导致 A3-05：
- 三个解明系 codex **丢失 `id`**；
- `hasJiemingConstellation` 的 `entry.id?.startsWith("jieming")` **恒为 undefined** → 函数永远返回 false（**静默失效**）。

**处理（规范勘误 E1）**：
- `ConstellationCodexEntry` 增补**可选**字段 `id?: string`（其余 5 系统无需改动，向后兼容）；
- MANAPHY群 / MELOETTA / MEW 三个 codex 首条补 `id: JIEMING_MODULE_ROOT`；
- 勘误登记于 `A3-迁移规范.md §8.1`。

## 6. 坑③（附带发现）动画 chunk 接入路径（勘误 E2）

产物主 chunk 的 `JiemingResolvePhase.start()`：
```js
GR(async () => {
  const { playJiemingSkillAnim } = await import("./jieming-anims-D_uicwAh.js");
  return { playJiemingSkillAnim };
}, __vite__mapDeps([0, 1, 2]), import.meta.url)
  .then(({ playJiemingSkillAnim }) => playJiemingSkillAnim(user, skill, targets))
  .catch(err => console.warn("[解明] 动画播放异常，跳过动画直接结算", err))
  .then(() => { skill.apply(user, targets); ... });
```

**接入路径说明（交付项 ③）**：
1. 动画脚本是**独立 chunk**（约 327 KB），产物用 vite `__vite__mapDeps` + 动态 `import()` 加载；
2. 迁移树新增**占位模块** `jieming-anims.ts`，导出 6 个产物函数（`playJiemingSkillAnim` 为对外唯一导出，产物名 `$0`）；
3. `JiemingResolvePhase.start()` 用 `await import("./jieming-anims.js")` 动态引入；占位实现立即 resolve（等价「无动画 → 直接结算」，与产物 `.catch` 降级路径殊途同归）；
4. **A3-13** 用真实 chunk 源码替换占位实现，**导出名保持不变**；`__vite__mapDeps` 由打包器自动生成，源码无需手写。

> 这也**顺带修掉了 A3-05 HEALER 的 `TS2307`**：原先 HEALER 内联的 `import("./jieming-anims.js")` 无法解析，现已由占位模块承接。
