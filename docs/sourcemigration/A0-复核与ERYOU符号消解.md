## ② ERYOU 符号消解：**第一步完成，解析率 22.4%**

### 2.1 方法（带符号消解）

利用产物的 **keepNames 注记** `l(短名,"原名")`（A3 阶段已确认是「短名 → 原名」的唯一命名来源）：

| 步骤 | 做法 |
|---|---|
| 1 | 取 ERYOU 两文件的 `declare` 名（**去重 755**：system 327 + ui 486） |
| 2 | 从产物全 chunk 抽 keepNames 映射（含 `l`/`r`/`c` 三种包装名，**2,819 条**） |
| 3 | 求交 → 得「可解析的 短名 → 原名」 |

### 2.2 结果

| 指标 | 数量 | 占比 |
|---|---:|---:|
| ✅ 可经 keepNames 解析 | **169** | **22.4%** |
| ❌ 未解析（需作用域分析） | **586** | **77.6%** |

**已解析样例**（说明方法有效）：
```
$ae → abyssAttackBuffMultiplier    A1  → EryouSubScreenHandler
AL  → levelCapOfProgress           AM  → chancePercent
Aae → isBetterKickCandidate        BCe → isZMove
CM  → hittableTargets              DB  → levelUpCostPreview
```

**未解析样例**：`$` / `$ge` / `AEe` / `ArrowDown` / `BA` / `BERRY` / `ERYOU` / `Enter` / `Esc` …

### 2.3 未解析的 586 是什么（**为什么 keepNames 不够**）

keepNames 只覆盖**具名函数/类**。以下**不产生注记**，必须靠**作用域分析**：
- **枚举成员 / 常量**（`BERRY`、`ERYOU`、`BA`、`GO` …）
- **对象属性 / 局部变量 / 参数**（`$`、`AEe`、`Afe` …）
- **上游 UI 基类与按键常量**（`Enter` / `Esc` / `ArrowUp` …，多为第三方或全局）

| 步骤 | 说明 | 预估 |
|---|---|---|
