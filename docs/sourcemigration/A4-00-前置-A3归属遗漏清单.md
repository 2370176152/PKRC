## 2. 方法（可复现）

### 2.1 方法一：中文串锚点覆盖率（主判据）

**原理**：锚点树上游的 JS 产物**不含中文字面量**（文案全在 `locales/*.json`）⇒ 产物 JS 里的 CJK 片段**全部来自 mod**，可直接当 mod 代码指纹。

```
产物 CJK 片段（按 [\u4e00-\u9fff]{2,} 切分、去重）
  ∩  迁移树（A3 暂存区 + 已接入锚点树的 mod 文件）CJK 片段
  =  已覆盖
```

| 项 | 数值 |
|---|---:|
| 产物 CJK 片段（并集） | 4,215 |
| 迁移树 CJK 片段 | 5,566 |
| ✅ 已覆盖（交集） | **2,462** |
| ❌ 未覆盖 | **1,753** |
| **覆盖率** | **58.41%** |

> 产物分布：`loading-scene` 3,307 · `legendary-popup` 814 · `index` 114 · `legendary-helper` 7 · `jieming-anims` 3

对产物中每个 `l(短名,"原名")` 符号取定义体窗口，按其中的 `z("domain",…)` 域标签 + 中文关键词归入系统，再与迁移树 export 求交。

\* 域聚类把「上游函数恰好同域」计入分母，故单列完成度不可靠；**合计口径（57.3%）与中文串法一致**。

### 2.3 方法三：③ 类池三方差集


| **C. 先固化口径，M4 走查驱动补迁**（**推荐**） | ① 现在把「口径修正 + 缺口清单」写入文档并公示；② A4-00 按原口径收尾；③ **A4-01 走查按本清单逐项验证**，走查暴露项即为「A3-补」任务源；④ 补完后重跑 A4-00b | 以**实测**代替估算；避免过度设计；走查本来就要做 | 需接受 A4-01 首轮「大量失败」，节奏上要预先对齐 | 走查内消化（不额外增加排期） |

**推荐 C 的核心理由**：A4-01 的验收标准本身就是「11/11 不抽样 + 证据」，它**天然是缺口发现器**。与其现在估算缺口工作量（估算误差大），不如把本清单作为**走查用例的驱动表**，用实测结果驱动补迁 —— 这也符合本项目的「以产物为准」原则。

**但有一个前提必须现在做**：把「A4-00 口径 = 22 文件可编译，≠ 功能等价」**写进文档并公示**，否则 M4 会把「M3 范围缺陷」误判成「M3 交付缺陷」。
