```

        产物中搜索 `[{name:"系统名",description:...}]`

Step 3  提取函数实现
        python .build-tools/extract-symbol.py <函数名>
        形态：function 短名(...){...}l(短名,"原函数名")

Step 4  解析常量
        grep 常量符号定义 `const/let/var X = ...`

Step 5  写 TS
        - 函数名还原（l() 反查原名）
        - 常量加数值 + 产物符号对照注释
        - 中文串逐字保留
        - 依赖处标 TODO(接入锚点)

Step 6  验证
        node <tsc> --noEmit --skipLibCheck <file>.ts   # 语法零错误
        （A4 阶段再做行为等价验证）
```

## 4. 架构洞察：自研系统的统一模式

从 NIANLI 逆向可看出，**6 大系统共用同一套「命座框架」**：

```
命座注册: registerConstellation(species, codex[], { exclusiveNodes: [...] })
节点判定: constellationNodeIsExclusive(rootSpecies, node, ptSoudacheData)
数据存储: pokemon.customPokemonData.<system>Stacks / <system>GainTurn ...
招式钩子: apply<System>OnMoveUse(pokemon, move, targets)
回合钩子: on<System>TurnStart(pokemon)
```

⇒ **A3 应优先迁移这套「命座框架」**（`registerConstellation`/`constellationNodeIsExclusive`/`getConstellations`/`hasExclusiveNode`），它是所有系统的公共底座。

### 命座框架函数（已定位，待迁移）

| 产物 | 原名 | 作用 |
|---|---|---|
| `hI` | `registerConstellation` | 注册系统命座 |
| `US` | `constellationNodeIsExclusive` | 判定节点是否专属激活 |
| `sa` | `constellationLevel$1` | 读命座等级 |
| `HM` | `getConstellations` | 取命座列表 |
| `SU` | `hasExclusiveNode$1` | 是否含专属节点 |
| `OEe` | `constellationChoiceOptions` | 命座选项 |
