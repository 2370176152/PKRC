# A4-00b 剩余特性作战计划（2026-10-17）

> **背景**：上游 patch 清单 §3.1 的 32 宿主已补/已闭 **25**，剩 7 项 —— 全部为**特性级**
> （不再是「单点接线」，每项都含未迁函数/类 + 依赖闭包）。
> **本计划目的**：给出每项的量化体量、依赖现状、改动面、风险与建议顺序，供 owner 排期决策。
>
> **度量口径**：体量 = 产物（`loading-scene-By2k7Qfx.js`）中该函数/类的最小完整源码字符数（去混淆后）；
> 字符数与 TS 行数换算 ≈ 1 行 / 22~28 字符（含解出的中文串）。依赖「存在/缺失」= 在锚点树 `src/` 中
> 有无真实定义（非 declare）。

## 1. battleInfo 显示（dOe / MOe）—— ⭐ 最小、最先

**缺口**：三个微函数（产物侧均为 1~3 行）：

| 符号 | 产物定义 | 体量 |
|---|---|---:|
| `dOe` = showBattleInfoExclusively | `if(!(n && gameMode.isP5X)) for(const A of getField()) A && A.isPlayer()===n.isPlayer() && A.setBattleInfoVisible(A===n)` | ~130 |
| `MOe` = showBattleInfoForActorOnly | `if(!(n && gameMode.isP5X)) for(const A of getField()) A && A.setBattleInfoVisible(A===n)` | ~120 |
| `setBattleInfoVisible`（**mod 新增 Pokemon 方法**） | `setBattleInfoVisible(s){ this.battleInfo?.setVisible(!rr(gameMode) && s) }` | 67 |

**依赖**：`E.getField()` ✓ · `Pokemon.isPlayer/`battleInfo` ✓ · `rr`（P5X 判定，需核对是否已有等价 `gameMode?.isP5X`）。

**改动面**：`healer/eryou/p5x` 三系统各 1 文件加导出 + `mod-augment.ts` 合并 `Pokemon.setBattleInfoVisible`
（或直接加到 Pokemon 类）+ 约 **10 处调用点**（TurnStartPhase 同伴调用、Search UI、Command/TargetSelect 等）。

**验收**：`tsc/build EXIT=0`；新鲜产物出现 `showBattleInfoExclusively`/`showBattleInfoForActorOnly`/`setBattleInfoVisible`。

**风险**：低（纯显隐控制）。唯一注意点：`setBattleInfoVisible` 是 Pokemon 方法 ⇒ 走 mod-augment 声明合并，
不要让 `tsc` 的 declaration merging 与 `battle-info` 组件签名冲突。
