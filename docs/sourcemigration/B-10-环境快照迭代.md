## 二、为什么要迭代：B-6 覆盖的是「锚点树内」，B-10 要覆盖「宿主机上」

两件事的性质不同，失效方式也不同：

| | 构建环境（B-6 已有） | 走查环境（B-10 新增） |
|---|---|---|
| 依赖位于 | **锚点树内**：`node_modules` / 原生绑定 / `tsconfig` | **宿主机上**：Node 解释器能力 / 浏览器 / A·B 产物目录 |
| 失效表现 | **响亮**：`tsc`/`vite` 立刻报错 | **安静**：浏览器找不到、Node 没有 `WebSocket` ⇒ 跑不起来或空跑 |
| 谁受影响 | 全栈 / 构建者 | A4-01、A4-04（O-9 唯一授权的 GUI 实测路径） |

**安静失效更需要机器校验** —— 这是本次迭代的全部理由。

## 四、校验器新增 `[7/7] 走查环境`

`tools/verify-env.cjs` 由 6 段扩到 7 段，新增内容与判据：

| 检查 | 判据 | 失败的后果（写进输出，不只报错） |
|---|---|---|
| 运行器 Node | 主版本 ≥ 22 **且** `globalThis.WebSocket` / `fetch` 可用 | 指出 `shared/runtime/node.exe`（16.16.0）**不能**用于走查 |
| 浏览器 | 按候选顺序找到可执行文件 | 列出**试过的全部路径**；提示装浏览器或设 `PKRC_BROWSER` |
| `PKRC_BROWSER` 设了但不存在 | **判失败** | 说明 `browser.mjs` 会**静默回退**、证据包会挂错来源 |
| 零 npm 依赖 | 扫描全部 `.mjs` 的 import：只允许 `node:` 与相对路径 | 列出违规的「文件 → 包名」 |
| 仓内依赖 | `tools/input-layer/input-arbiter.js` 存在 | input-smoke 场景会跑不了 |
| A / B 产物根 | 两个目录都存在 | A 缺失时提示「只能跑单产物，失去 O-9b 基准」 |

**新增 `--wt-only`**：只校验走查环境、不要求锚点树。
用途明确 —— 一台只负责跑走查出证据的机器（A4-01/A4-04 的证据机）不需要装锚点树与 `node_modules`，
不该被「锚点树不存在」挡住。

### 4.1 两个设计细节（都是为了「不漂移」）

1. **浏览器候选路径从 `tools/walkthrough/lib/browser.mjs` 原文提取**，不在校验器里硬编码。
   装了 Chrome 或换了路径，只改 `browser.mjs` 一处，校验器自动跟随。
   （提取失败时退回内置兜底清单并**显式告警**，不静默。）
2. **浏览器版本零 spawn 获取**。Windows 上 `msedge.exe` 是启动器存根：`--version` **零输出**（实测 EXIT=0），
   spawn 根本问不出东西。版本号唯一可靠的来源是安装目录下的 `Application/<x.y.z.w>/` **目录名**。

## 五、🔴 三个 Node 的用途矩阵（新机器最容易踩的坑）

用错 Node **不会报「版本不对」**，只会构建失败或走查空跑。故写进 runbook（§十一.1）与本节：

| 用途 | 用什么 | 本机实测 | 语法上限 | 用错会怎样 |
|---|---|---|---|---|
| 运行期 `server.cjs` | `shared/runtime/node.exe` | **16.16.0** | `game/server/**` 限 Node 16 语法 | 用了高版本语法 → **玩家侧崩、开发机测不出来** |
| 构建期 `tsc`/`vite` | `.build-tools/node-v24.9.0-win-x64/` | **24.9.0** | 无 | 用 16 跑 vite 8 → 直接起不来 |
| 走查期 `tools/walkthrough/**` | PATH 上任意 `node` ≥22 | **22.22.2** | 需 `WebSocket`/`fetch` | 用 16 跑 → `WebSocket is not defined` |

## 八、遗留与边界（如实）

1. **「新机器」没有第二台机器可用。** 本报告做的是：
   (a) 把从零复现写成**可执行 runbook**（`环境搭建文档.md` §十一）；
   (b) 把 runbook 里**每一条命令**在本机实跑一遍；
   (c) 把「环境是否满足复现条件」变成 `verify-env` 的**机器判据**。
   **未验证**的路径：真正空的 OS、**冷 pnpm store**（需联网下载全部依赖，继承 B-6 §10.7 的同一条局限）、
   非 Windows 平台。风险：这些路径上的失败模式只能靠 runbook 里的「坑」章节预先提示。
2. **浏览器版本变动只做提示，不判失败。** Edge 自动更新会让版本号天天变；
   判失败等于制造噪声。但会在输出里提示「像素 diff 的差异率**不可与旧证据包直接比**」。
3. **零依赖检查只扫直接 import。** 不递归解析被引入的仓内文件
   （如 `tools/input-layer/input-arbiter.js` 自身是否依赖 npm 包）。
   当前该文件无 npm 依赖，但**这是人工确认的，不是机器保证的**。
4. **`lib/browser.mjs` 的静默回退未改。** 那是 F-10 的交付物，改动属他人职责。
   本次只在校验器侧把它顶出来。**建议** F-10 的所有者考虑让 `PKRC_BROWSER` 指向不存在时直接报错
   —— 这与本项目已登记过的「静默 fallback」bug 是同一类。
5. **走查报出的产物问题不属 B-10 范围**：A 版 16 项 404（P4-R10 已知）、
   B 版 `safeT is not defined`（P4-R4 → A4-00b-2）。B-10 只保证**环境能把它们跑出来**。
6. **`--snapshot` 必须用构建期 Node 执行**，否则 `toolchain.node` 会记错。
   已在 runbook §11.6 显著标注；但脚本本身**没有**强制校验这一点（加校验需要 spawn 或额外标记，代价不值）。
7. **`game/server/.release-staging/dist.new` 约 349 MB 测试残留**（B-9/B-7 期间产生）仍在那里，
   清理需授权（已在 B-7 报告 §九.6 登记）。
