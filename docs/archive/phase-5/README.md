**F-14 的核心设计：五态裁定**

| 态 | 含义 |
|---|---|
| `pass` | 通过 |
| `fail` | 不通过（真缺陷） |
| `unproven` | 无法证明（**不得声称已走查**） |
| `unreached` | 未到达该画面 |
| **`blocked`** | **产物无该画面 = 迁移缺口 ⇒ 不计失败**，进 L2/L3 台账 |

> **`blocked` 这一态是让走查"能跑完"的关键** —— 否则 UI 缺口会把整轮走查淹没成一片红，
> 无法从中分辨"真缺陷"。

**⚠️ 如实记录的遗留**：`routeReliability` 分布 **verified 2 / derived 22 / unknown 27**
⇒ **51 点中 27 点尚无到达依据**，直接跑会大量出现 `unproven` / `unreached`。

## 六、🔴 已定位的模式缺陷（第六阶段的设计依据）

**连续三个阶段的形态完全一致**：

| 阶段 | 建成了什么 | 判据/里程碑 |
|---|---|---|
| 第四阶段 | 10 项能力（F-10 走查环境 · B-7/9/10/11 · A4-03） | **0 / 7** |
| 第五阶段 | 走查全链路（51 点 · 五态裁定 · 闸门 · 取证 · 回归 · 演练） | **1 / 7** |
| **共同点** | 「建工具」占满整个阶段，「用工具」没有开始 | — |

**根因不是执行力，是规划**：每个阶段都把「**建成使能件**」和「**执行验证**」放进同一阶段，
而使能件本身就要吃掉整个阶段。

**⇒ 第六阶段的硬约束**：

> **禁止新建任何工具 / 使能件 / 框架。只允许"执行既有能力 + 修被暴露的缺陷"。**
> 若确需新工具，必须由所有者批准并说明为何现有能力不够。
