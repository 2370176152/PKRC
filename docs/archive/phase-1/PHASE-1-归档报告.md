## 一、阶段定位

第一阶段解决的是**一个根本问题**：

> 仓库里**没有 TypeScript 源码**，只有 Vite 构建产物（`game/server/dist/`）。
> 所有魔改都是对压缩产物的**字符串补丁** —— 上游一更新，chunk 哈希全变，补丁全废。

阶段目标因此定为：**把"产物即源码"的不可维护状态，换成"有版本控制 + 可追溯魔改地图"的可维护基线。**

| 维度 | 阶段前 | 阶段后 |
|---|---|---|
| 版本控制 | ❌ 无（`fatal: not a git repository`） | ✅ 11 提交 / 分支 `sourcemigration` |
| 上游对应 | ❌ 未知 | ✅ V1.11.22 / 基线 `90df65097b6d` |
| 魔改可追溯 | ❌ 仅 7 条手写补丁描述 | ✅ 3,086 锚点 / 297 类 / 11 系统 |
| 魔改点定位 | ❌ 人工翻产物 | ✅ 中文串锚点法 + 类名映射表（半机械化） |
| 迁移底座 | ❌ 无 | ✅ 命座框架 14 函数 |
