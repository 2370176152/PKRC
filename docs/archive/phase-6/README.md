### 3.2 🔴 H-1 的两个重大发现

#### 发现一：PT 地基整体缺失（规模远超"4 方法"）

| 缺失项 | 状态 |
|---|---|
| `GameData.pt` 字段 | ❌ 只在 `mod-augment.ts` 声明，`game-data.ts` **零实现** |
| `ptSoudacheData` 字段 | ❌ 同上 |
| 序列化 / 读回 | ❌ 同上 |
| `addPt` | ❌ 同上 |
| `getDailyStarters` / `applyDailyStarters` | ❌ 同上 |
| `initPtSoudacheData` / `getEryouData` | ❌ 同上 |

**共 9 项全部只有声明、没有实现。**

> **后果**：即便通关流程方法写完，**一次 `addPt` 就会因 `this.pt` 未定义而崩**。
> **⇒ PT 判定只能到 🟡，不能到 ✅。** 这是 H-1 最重要的产出 —— 它阻止了"验收全绿但一跑就崩"。

**H-1 的其他偏差（如实）**：
- 派单说"通关流程 4 方法"，实际 **5 方法**（漏了 `continuePtVictoryFlow`）
- 派单说 `carryOutAwakeningStones` 属 PT，实际守卫是 `gameMode.isP5X && isVictory` ⇒ **属 P5X**
- 守门员 19 处：实际 **9/12 逻辑点**接线，3 处受下游缺失阻塞

#### 发现二：`clear-declares.cjs` 存在 P0 级判据缺陷（已修）

| 项 | 内容 |
|---|---|
| **症状** | 该工具把 10 处 declare **全判为「D 类误捕·可直接删」**（真实依赖 0） |
| **根因** | `execFileSync("node_modules/.bin/tsc")` 在 Windows 下指向 **shell shim** ⇒ ENOENT ⇒ 异常 ⇒ **输出为空** ⇒ 所有 declare 都被当成误捕 |
| **修法** | 改为 `node <typescript>/lib/tsc.js` + ENOENT 显式 `exit(2)` |
| **结论反转** | **10/10 全是真实依赖，0 误捕**；手工删 declare 实测 **15 个 TS2304** 证实 |

> **这是"工具本身在说谎"的典型案例。**
> ⇒ 此前基于 `clear-declares.cjs` 得出的**所有"declare 可清理"结论都不可信**，须重新核。
