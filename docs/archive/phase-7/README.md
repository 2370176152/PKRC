### 3.2 🔴 5 个 P0（全部只有真跑才现形）

| # | 报错 | 根因 | 修法 | 严重度 |
|---|---|---|---|---|
| 1 | `safeT is not defined` | 悬空 `declare`，但 `TALENT_POOL` 在**模块求值期**调用 | 实现产物 `es`（`i18next.t` + 空串回退） | 阻断启动 |
| 2 | `FixedBattleConfig is not a constructor` | **循环导入** `battle → modifier → pt-soudache-system → title-phase → game-mode → fixed-battle-configs → battle` | ① `TitlePhase` 改 `pushNew` ② 守门员数据表拆到零副作用 `pt-guardian-data.ts` | 阻断启动 |
| 3 | `createSpeciesPartyWeightModifiers is not defined` | 同 1，走**启动路径** | talent 剩余 6 项 declare 全部实现 | 阻断启动 |
| **4** | **B 停在登录页**（非报错） | **构建 mode 错**：`vite build` 默认 `production` ⇒ `VITE_BYPASS_LOGIN=0` | 改用 `vite build --mode app` | 🔴 **最严重** |
| 5 | `ii / Ht / $l / Yi is not defined` | 15 处 `extends <declare 短名>` 在**模块求值期**继承 | `ii` 换真实 `Phase`；其余 4 个（L3 未接线 UI 基类）用空类占位 | 阻断启动 |

#### P0#4 为什么最严重

`vite build` 读 `.env.production`（`VITE_BYPASS_LOGIN=0`）⇒ 编译期 `bypassLogin=false` ⇒ **必须登录**。
而 modder 原产物 A 是 `bypassLogin=true`。

**⇒ 此前所有走查（第五/六/七阶段）测的都是「登录页上点几下」。**
实证：修后产物内 `Log in or create an account` 由 **1 → 0**；截图显示 B 首次进入游戏欢迎页。
