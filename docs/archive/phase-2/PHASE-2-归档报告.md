## 七、经验沉淀（方法论级）

| # | 沉淀 | 来源 |
|---|---|---|
| 1 | **"沉默的迁移错误"最危险** | E3（`gainKey` vs `Pokemon`）不报错、不崩溃，只是功能静默失效 → **必须逐符号对产物比对，不能只信 tsc** |
| 2 | **构建通过 ≠ 迁移正确** | A3-13 的 `vite build` 是绿的，但签名一致仅 58.51% → **构建成功只证明语法与依赖没问题** |
| 3 | **签名比对是最高价值的等价性代理指标** | 2,704 个具名符号的全 chunk 并集比对，能一次性暴露"未命中"的三类根因 |
| 4 | **混淆产物原样保留，不"顺手统一"** | `FlipStatAbAttr` vs `FlipStatChallenge` 映射不同，迁移时**不统一** → 避免引入不可追溯的行为变更 |
| 5 | **阶段边界会因实测发现而后移，如实记录即可** | PE-4~PE-7 后移不是失败；**假装完成才是** |
| 6 | **口径治理也是交付** | 「轮」被弃用、统一为「阶段 + 任务编号」—— 编号混乱会直接导致归档对不上账 |
| 7 | **环境问题与代码问题必须分开归因** | 7 处 tsc 错全是环境（子模块未初始化 / vite 版本错配），若混为一谈会误判迁移质量 |
